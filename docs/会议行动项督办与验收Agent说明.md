# 会议行动项督办与验收 Agent 说明

## 产品目标

会议纪要不再停留在“生成了几个任务”。系统把每个已确认行动项视为一项可追踪承诺：正式任务是唯一执行事实源，督办服务负责发现失联、定义不完整、临期、逾期和阻塞；Agent 只负责解释与建议，不能修改事实或代替人工验收。

## 运行链路

```text
会议确认 → 行动项关联正式任务 → 15 分钟自动检查 / 人工立即检查
       → 计算督办状态与 L1-L3 → 写入唯一督办事件 → 项目内分级通知
       → 会议详情展示状态、原因、检查时间与提醒次数
```

同一状态的普通扫描不会产生事件。持续需要关注时每天最多提醒一次；状态改变或升级等级改变时立即生成新事件。`EventKey` 有唯一索引，多次扫描不会重复写入同一个信号。

## 两个内置 Agent

### 会议督办 Agent

- 必须关联有权限的项目和任务；
- 读取任务、评论、最近会议、正式交付凭证和会议承诺督办记录；
- 输出督办结论、证据、阻塞/逾期原因、建议升级、下一动作和下一检查时间；
- 允许调度器匹配“督办、催办、逾期、阻塞、行动项”等任务；
- 没有工具权限，不自动写评论。

### 交付验收 Agent

- 从交付凭证页面手工启动，审查当前任务最新交付；
- 输出明确的“建议通过”或“建议驳回”、证据覆盖、缺失项、工具影响、风险和人工复核点；
- 不参与普通任务自动派单，避免替换原执行 Agent；
- 没有工具权限，不能更改正式验收状态。

## 权限与通知范围

- 督办扫描只处理已经确认、会议未删除的行动项；
- 页面沿用会议项目访问权限，立即检查沿用会议写入审批权限；
- L1 通知会议/任务创建人和人工责任人；
- L2/L3 再加入任务审核人、项目负责人和项目管理员；
- 接收人必须是有效账号，不向无关项目或所有系统管理员广播；
- Agent 上下文仍先校验当前用户项目权限。

## 自动化验证

测试覆盖：临期同日幂等、逾期从 L1 升级 L2、项目管理层收件范围、完成状态只审计不提醒、交付凭证与会议承诺进入 SelectedTask 上下文、两个内置 Agent 已发布且无工具权限。
