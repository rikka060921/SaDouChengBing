# Agent 会议验收、任务分组与会议缓存修复说明

基于 `4f8f26b` 的本地复查结果修复。范围是三项已经复现的问题及相关边界场景；本次不访问线上、不修改真实业务数据。

## 一、会议行动项与 Agent 验收状态不一致

此前，会议行动项把已有任务从“待审核”改为“已完成”时，只调用普通任务状态设置。Agent 执行状态、交付回执和关联议题仍停留在待验收；改回“进行中”也不会产生返工工作项。

本次修改：

- 扩展 `TaskReviewService.StageReviewAsync`，让会议确认和原有议题验收复用审核权限、任务与 Agent 状态、交付回执、表现反馈、审核评论、日志和通知的处理逻辑。
- 会议明确通过待审核任务时，同步完成任务及 Agent 验收，归档该项目内关联的活跃议题，保存归档会议及关联关系。
- 会议明确将待审核任务打回进行中时，累计返工次数、驳回交付记录、取消旧的活跃工作项，再通过现有 `AgentWorkQueueService` 建立带审核意见的返工工作项。幂等键关联任务、审核评论及 Agent。
- 审核、评论、队列、议题及会议确认都置于原有会议事务内。即使取得评论主键时执行了中间保存，后续审计失败仍会整体回滚；重复确认不会重复返工、重复通知或重复记录表现反馈。
- Agent 已停用导致无法入队时，保留队列服务原有的明确失败状态和原因，不展示虚假的待执行工作项。
- 确认前检查会议草案记录的任务状态是否已过期，拒绝覆盖最新进展；无效目标状态不再默默变为未开始；Agent 尚未提交待审核结果时，不能通过会议直接标为完成。

这不是对历史异常数据的批量修复。已经存在的错误状态、缺失验收记录需要单独核对，不能直接从“任务已完成”推断当时的真实验收结论。

## 二、分组加载中保存造成任务分组丢失

此前，分组异步请求开始时会清空选择，但保存按钮仍可用，空值会被后端当作“不分组”。编辑弹窗立即确定并保存也存在同样问题。

本次修改：

- 统一列表行和编辑弹窗的分组加载逻辑，为每个选择框维护加载状态。
- 同项目刷新时保留原选择；加载中禁用选择框及对应保存操作，表单提交函数也做二次拦截。
- 加载失败保留原选择，显示可点击的重试按钮；不能直接把加载失败当成“不分组”提交。
- 每次加载有独立请求序号，快速切换项目时，过期成功或失败响应都不能覆盖最新项目的分组。
- 浏览器返回页面时按真实加载状态恢复按钮；已删除的任务行不阻塞其他任务保存。
- 正常返回空分组列表时仍支持“不分组”，跨项目分组继续由后端拒绝。

## 三、腾讯会议异常 JSON 破坏缓存回退

此前，合法 JSON 中的错误结构（例如 `[]`、`{"data":null}`）会触发 `InvalidOperationException`，只捕获 JSON 语法异常无法兜底。

本次修改：

- 检查根节点、`data` 和转写 `minutes` 的对象类型。
- 会议列表和转写解析同时处理 JSON 语法错误及字段类型错误，异常响应优先回退已有有效缓存。
- 没有缓存时，会议列表返回空集合，转写返回可理解的“尚未生成或返回格式无效”提示。
- 原始转写也在校验成功后才写入缓存，避免无效响应覆盖同时间戳的有效文件。
- 在线正常返回空会议列表仍更新缓存；恢复正常后刷新能获取最新会议和转写，不会被旧缓存锁住。

浏览器用例使用最小页面夹具和生产脚本，不等同于完整真实账号的页面端到端测试。真实 AI、腾讯会议供应商在线可用性、生产部署及线上数据状态不在本次验证范围。

## 部署与人工验收

本次没有新增数据库迁移，也没有修改配置、账号或密钥。需要发布完整后端及 Razor 页面；如服务器尚未包含上一版的迁移，仍需按上一版说明完成升级。

1. 找一条 Agent 已提交待审核结果的任务，在会议行动项中确认完成；检查任务已完成、Agent 已完成、回执已通过、审核人及时间、议题归档会议一致。
2. 另建一条待审核 Agent 任务，在会议中打回进行中；检查返工次数增加、回执已驳回、旧活跃工作项取消、新返工工作项带有审核意见。重复确认不产生第二份返工。
3. 对任务拆分页面模拟慢网络，加载完成前不能保存；恢复后保存，任务保留已选择的分组。模拟失败后重试，仍应保留原选择。
4. 快速切换任务所属项目，最后显示的分组必须属于最后选择的项目。
5. 腾讯会议存在有效缓存时，模拟异常响应应仍能读取旧数据；恢复正常后应可刷新到新内容。
