# Agent 真实项目演示手册

## 1. 演示目标

用一套接近真实交付现场的数据，演示用户只创建任务、不选择具体数字员工后，系统如何完成自动调度、权限隔离、项目上下文读取、任务执行、交付验收和高风险人工审批。

演示场景为“星桥智造 · 华东 20 店智能巡检上线”。所有公司、人员、门店和业务数据均为模拟数据，不对应真实客户。

## 2. 一键创建的内容

运行初始化脚本后，系统会创建：

- 1 个智能巡检上线项目，包含上线目标和量化验收标准；
- 6 个业务任务，覆盖已完成、进行中、未开始、不同优先级和截止时间；
- 2 场会议纪要，包含会议原因、议题、决策、行动项和可定位的转写原话；
- 1 份 Word 项目方案，自动上传到“需求与目标”分类并等待知识索引完成；
- 1 条 `project-workbench` 只读资料权限，不授予写权限；
- 1 个只读 Agent 任务，由调度器自动选择 Agent，完成后停在“待人工确认”；
- 1 个高风险变更任务，由 Agent 调用 `task.update`，停在“等待敏感操作审批”。

脚本会自动检查项目、任务、会议、资料索引、Agent Session、证据链、只读边界和审批门禁。任一环节不符合预期都会返回失败并写入 JSON 报告。

## 3. 服务器部署后初始化

推送并发布代码、执行数据库迁移、确认网站健康检查和 AI 配置正常后，在仓库根目录运行：

```powershell
$credential = Get-Credential
./deploy/Test-ToDo-AgentE2E.ps1 `
  -BaseUrl 'https://你的站点地址' `
  -Credential $credential `
  -DemoMode `
  -AgentTimeoutSeconds 300 `
  -OutputPath './artifacts/agent-demo-result.json'
```

请输入具备项目创建、Agent 执行和审批管理权限的演示账号。不要把账号密码写入脚本或提交到 Git。

默认会保留演示项目，方便现场演示。只有临时回归测试才加 `-ArchiveAfterRun`。代码推送不会携带本地数据库中的演示项目，所以服务器发布后必须在服务器地址上再运行一次初始化命令。

## 4. 推荐现场演示流程（8—10 分钟）

### 第一步：项目不是空壳

进入“项目管理”，打开最新的“星桥智造”演示项目。展示项目目标、门店范围、目标上线日和验收指标。

进入任务页，说明真实项目并非全是未开始状态：其中有已完成基线、有三个进行中任务，也有依赖门禁的灰度和扩容任务。

### 第二步：Agent 能读取受控项目资料

进入“项目资料”，展示 Word 方案状态为“可检索”，分类为“需求与目标”。

向下展示 Agent 分类资料权限：`project-workbench` 只有读取权限，没有写入权限。强调资料权限是项目级、Agent 级、分类级三层约束，未授权默认拒绝。

### 第三步：会议纪要能回到真实原话

进入“会议纪要”，打开“上线门禁评审会”或“弱网与告警误报风险复盘会”。

展示结构化决策与行动项，再点击关键原话定位到转写正文。强调页面上标为“原话”的内容必须来自真实转写，不允许模型凭空生成。

### 第四步：用户只选数字员工，不选具体 Agent

打开任务“输出灰度上线 7 天行动简报（Agent 自动调度）”。展示：

- 系统已根据能力、项目权限、风险、负载和历史表现选择 Agent；
- 执行时间线从待执行进入执行中，再进入待人工确认；
- Session 中只有 `context.read`，没有 `task.add_comment` 或其他业务写入工具；
- 最终简报同时引用项目、任务、会议和 Word 项目资料；
- 正式交付凭证记录证据、工具影响、内容哈希和验收状态。

现场使用有验收权限且符合独立复核规则的账号点击“验收通过”，即可演示任务从“待人工确认”进入正式完成。也可以选择“退回重做”，展示人仍然拥有最后决策权。

### 第五步：高风险操作必须停下来等人

打开任务“调整本任务交付截止时间（人工审批演示）”。展示任务状态为“等待敏感操作审批”，然后进入审批中心：

- 工具调用是 `task.update`；
- 风险等级为高风险；
- 在人批准前，截止日期没有变化；
- 由另一位具备项目审批权限的账号审批通过后，工具才真正执行，工作项会自动继续；
- 审批拒绝时，业务数据保持不变，并保留拒绝记录。

高风险申请执行“发起人与审批人分离”，因此发起账号不会看到“通过并执行”按钮，只能驳回；正式演示审批通过时需要准备第二个项目管理员或系统管理员账号。建议提前打开两个任务页和审批中心作为浏览器标签，避免现场等待 Agent 运行。

## 5. 演示时的核心介绍话术

> 这不是一个只会聊天的机器人，而是一套受权限、证据和审批约束的数字员工运行系统。用户只需要创建任务并选择“数字员工”，调度器会决定由谁执行。Agent 先读取自己有权访问的项目上下文，再根据任务是否明确要求写回决定是否开放业务工具。只读任务由后端强制禁用写入工具；高风险变更必须进入人工审批。Agent 的结果不会直接把任务标成完成，而是形成带证据和哈希的交付凭证，最后由人验收。

## 6. 验收清单

- 演示初始化脚本返回成功，JSON 报告的 `Success` 为 `true`；
- Word 资料状态为“可检索”；
- 只读 Agent 任务状态为“待人工确认”，`ReadOnlyBoundaryVerified` 为 `true`；
- 只读 Session 的工具调用列表只有 `context.read`；
- 交付简报能看到项目、任务、会议和文档四类证据；
- 高风险任务状态为“等待敏感操作审批”；
- 高风险 Session 存在 `task.update`，但审批前任务截止日期未变化；
- 审批通过后工具执行且 Agent 自动续跑；
- 人工验收通过后任务才成为完成状态。

## 7. 清理与重复演示

每次运行会使用带秒级时间戳的项目名，因此可以重复初始化而不会误绑定旧项目。演示结束后，在项目列表点击“归档项目”即可隐藏该套数据；归档不会直接删除历史审计、Session、审批和交付凭证。
