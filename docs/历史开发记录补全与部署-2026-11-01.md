## 本轮实现

- 项目历程追加后续有来源阶段，保留原节点，不重写过去的承诺、完成率或验收结论。
- 项目导航“开发记录”展示当前分支完整可达 Git 历史，含提交 SHA、Git 署名、原作者/提交时间、修改摘要和文件路径，支持搜索、署名筛选和 30 条分页。
- Git 署名数量不等于自然人数量。当前团队四人的参与信息独立展示，按用户名关联目标环境账号；未知别名不强行认领。不存在或停用的账号不创建密码、不自动启用、不授予权限。
- Git 修改不是当年的系统操作。只有真实补录动作写入当前时间的操作日志，明确 `[历史补录]` 标记、来源 SHA、实际操作者和数量。
- 原 23 个任务及 14 组会议继续只读；不新建已过期的业务任务，不重新派单、催办或伪造日报。缺失日期、旧成员归属、未保存的早期任务细节继续留空。
- 项目资料复用现有文件库、分类、版本和 SHA256。原件字节保留，旧版本和旧项目不删；同一资料重复导入跳过。数据库记录存在但原件缺失且有已验证副本时可恢复；不同内容另存版本，不覆盖旧文件。
- 两份维护索引 `project-development-ledger.json` 和 `project-history-archive.json` 只能由项目管理人员上传替换或回滚，普通成员不能借资料上传权限伪造整份开发历史。
- Git 索引和原始会议属于私有运行数据，均写入忽略的 `artifacts` 或项目私有资料目录，不随源码推送公开 GitHub。Git 安全摘录会脱敏部分密钥/密码模式，原始业务资料仍须私有管理。

## ToDo2 服务器执行

先将私有 ZIP 复制到服务器 `C:\Deploy\SaDouChengBing-history-20261101.zip`。在管理员 Windows PowerShell 执行（不要把补录包或 SQL 放入 Git 仓库或站点公开目录）：

```powershell
git -C 'C:\Deploy\ToDo-source' pull --ff-only origin 'Work-miracles(SaDouChengBing)'
if ($LASTEXITCODE -ne 0) { throw '拉取失败，已停止' }

& 'C:\Deploy\ToDo-source\deploy\Complete-ToDoProjectHistory.ps1' `
  -SiteName 'ToDo2' `
  -SiteRoot 'C:\inetpub\ToDo2' `
  -SourcePath 'C:\Deploy\ToDo-source' `
  -PackageZip 'C:\Deploy\SaDouChengBing-history-20261101.zip' `

```

若只想先检查，去掉 `-Deploy -Apply`，脚本只预览，不停站、不部署、不写业务数据。若找不到备份工具，增加 `-MySqlDumpPath '本机实际的 mysqldump.exe 路径'`，不能用猜测的 MySQL 安装位置替代。

脚本步骤：确认单独的站点/应用池及干净源码 → 校验 ZIP 路径/大小和资料哈希 → 编译维护工具 → 读取现有 IIS 数据库配置 → 预览 → 停止目标应用池 → 备份数据库、App_Data、上传原件和旧 web.config → 调用原有 IIS 发布脚本 → 再暂停后台写入 → 事务补录 → 校验当前原件与报告 → 恢复应用池。

备份与报告位于 `C:\inetpub\ToDo2\maintenance-backups\history-*`，只允许管理员和 SYSTEM 访问，不放在公开 release 内。原部署脚本继续处理发布目录切换及失败时的代码回退；本脚本不自动恢复整库、不删除旧目录、不重置账号。导入事务失败会回滚；提交后的独立文件校验如有问题会返回失败并留下报告，需核查后再继续，不能把失败当成功。

服务器复用现有“撒豆成兵（正式开发）”（此前为 #20），实际编号以报告为准，绝不照搬本地 #19。已有历史档案、后续 Git 提交和成员权限保留；按稳定来源键合并。旧包不能覆盖已追加的较新历史。原站保留且有效的旧链接不改，本地导入的外站编号链接不启用。
