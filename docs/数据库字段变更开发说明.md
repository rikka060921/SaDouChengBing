# 数据库字段变更开发说明

## 1. 这份文档解决什么问题

本说明用于指导 `撒豆成兵 ToDo` 项目在实际开发中新增、修改或删除数据库字段。

项目使用 Entity Framework Core 管理数据库结构。数据库字段变化时，不要只在 MySQL 中手工修改，也不要只修改 C# 实体类，应通过数据库迁移让开发机和服务器保持一致。

可以把数据库迁移理解为一份“数据库升级记录”。

## 2. 最简单的操作流程

每次增加数据库字段，按照下面的顺序操作：

```text
确认字段需求
    ↓
修改实体类
    ↓
修改新增、编辑和详情页面
    ↓
检查后台保存逻辑
    ↓
生成数据库迁移
    ↓
更新本机数据库
    ↓
运行并验收
    ↓
提交实体、页面和迁移文件
```

## 3. 实际示例：给会议纪要增加“会议地点”

### 3.1 修改实体类

打开：

```text
ToDo.Entities/MeetingMinutes.cs
```

在 `MeetingMinutes` 类中增加：

```csharp
[MaxLength(100)]
public string? MeetingLocation { get; set; }
```

这段代码表示：

- 数据库字段名称为 `MeetingLocation`。
- 字段类型为文本。
- `?` 表示允许不填写。
- 最长保存 100 个字符。

### 3.2 修改新增页面

打开：

```text
ToDo.Razor/Pages/MeetingMinutes/Create.cshtml
```

在表单合适的位置增加：

```html
<div class="mb-3">
    <label asp-for="MeetingMinutes.MeetingLocation" class="form-label">
        会议地点
    </label>
    <input asp-for="MeetingMinutes.MeetingLocation"
           class="form-control"
           placeholder="请输入会议地点" />
    <span asp-validation-for="MeetingMinutes.MeetingLocation"
          class="text-danger"></span>
</div>
```

注意：页面实际绑定对象可能叫 `MeetingMinutes`、`Input` 或其他名称，应参考同一页面中已有输入框的写法，不要直接照搬对象名称。

例如页面原本使用 `Input.MeetingTitle`，新增字段就应该写成：

```html
<input asp-for="Input.MeetingLocation" class="form-control" />
```

### 3.3 修改编辑页面

打开：

```text
ToDo.Razor/Pages/MeetingMinutes/Edit.cshtml
```

增加相同的输入框，保证已有会议纪要可以修改会议地点。

### 3.4 修改详情页面

打开：

```text
ToDo.Razor/Pages/MeetingMinutes/Details.cshtml
```

增加：

```html
<div class="mb-3">
    <span class="text-muted">会议地点：</span>
    <span>@Model.MeetingMinutes.MeetingLocation</span>
</div>
```

### 3.5 检查后台保存逻辑

检查下面两个文件：

```text
ToDo.Razor/Pages/MeetingMinutes/Create.cshtml.cs
ToDo.Razor/Pages/MeetingMinutes/Edit.cshtml.cs
```

如果后台是逐个字段赋值，需要增加：

```csharp
meeting.MeetingLocation = Input.MeetingLocation;
```

编辑已有数据时可能是：

```csharp
existingMeeting.MeetingLocation = Input.MeetingLocation;
```

如果没有这一步，页面可能可以填写，但点击保存后字段不会进入数据库。

## 4. 生成数据库迁移

### 4.1 先停止正在运行的网站

在 Visual Studio 中点击“停止调试”，确认 `ToDo.Razor` 进程已经结束，避免 DLL 被占用。

### 4.2 打开程序包管理器控制台

Visual Studio 菜单：

```text
工具 → NuGet 包管理器 → 程序包管理器控制台
```

### 4.3 生成迁移文件

输入：

```powershell
Add-Migration AddMeetingLocation -Project ToDo.Context -StartupProject ToDo.Razor
```

`AddMeetingLocation` 是本次迁移名称，应使用英文，并说明本次修改内容。

常见命名示例：

```text
AddMeetingLocation
AddTaskReviewer
AddProjectDocumentCategory
MakeMeetingLocationNullable
AddTaskStatusIndex
```

生成的迁移文件位于：

```text
ToDo.Context/Migrations
```

## 5. 检查迁移内容

打开刚生成的迁移文件，检查 `Up()` 中是否只包含本次需要的数据库修改。

新增会议地点的迁移通常类似：

```csharp
migrationBuilder.AddColumn<string>(
    name: "MeetingLocation",
    table: "MeetingMinutes",
    type: "varchar(100)",
    maxLength: 100,
    nullable: true);
```

`Down()` 中应该有对应的回滚操作：

```csharp
migrationBuilder.DropColumn(
    name: "MeetingLocation",
    table: "MeetingMinutes");
```

如果迁移文件中出现大量与本次需求无关的表或字段变化，先不要执行 `Update-Database`，应检查实体和数据库快照是否发生异常。

## 6. 更新本机数据库

确认迁移内容正确后，在程序包管理器控制台输入：

```powershell
Update-Database -Project ToDo.Context -StartupProject ToDo.Razor
```

执行成功后，MySQL 中才会真正增加字段。

如果习惯使用 PowerShell，也可以在项目根目录执行：

```powershell
cd "D:\0.C#\Work miracles(SaDouChengBing)"

dotnet ef database update `
    --project ToDo.Context `
    --startup-project ToDo.Razor
```

查看迁移列表：

```powershell
dotnet ef migrations list `
    --project ToDo.Context `
    --startup-project ToDo.Razor
```

## 7. 本机验收

重新运行项目，至少检查以下内容：

- 新增页面可以填写新字段。
- 点击保存后没有报错。
- 详情页面可以正确显示。
- 编辑页面能正确回显旧值。
- 修改字段后可以再次保存。
- 修改前创建的旧数据仍然可以正常打开。
- 其他原有字段没有受到影响。

## 8. 提交代码

一次完整的数据库字段修改通常应同时提交：

- 实体类修改。
- Razor 页面修改。
- PageModel 或服务层保存逻辑修改。
- 新生成的迁移 `.cs` 文件。
- `ApplicationDbContextModelSnapshot.cs` 的自动变化。

不要只提交实体类而漏掉迁移文件，否则服务器数据库不会得到对应字段。

## 9. 服务器更新

服务器拉取最新代码并重新发布网站后，项目启动时会应用尚未执行的迁移。

正式发布前建议先备份 MySQL 数据库。发布后应检查：

- IIS 应用程序池是否正常启动。
- 网站是否可以登录。
- 新增、编辑和详情页面是否正常。
- `__EFMigrationsHistory` 是否包含最新迁移。

迁移记录可以通过下面的 SQL 查询：

```sql
SELECT MigrationId
FROM __EFMigrationsHistory
ORDER BY MigrationId DESC;
```

## 10. 不同字段类型怎么写

### 可选文本

```csharp
[MaxLength(100)]
public string? Remark { get; set; }
```

### 必填文本

```csharp
[Required, MaxLength(100)]
public string Name { get; set; } = string.Empty;
```

### 日期

```csharp
public DateTime? CompletedAt { get; set; }
```

### 数字

```csharp
public int SortOrder { get; set; }
```

### 是否启用

```csharp
public bool IsEnabled { get; set; }
```

### 关联用户

```csharp
public int? ReviewerId { get; set; }

[ForeignKey(nameof(ReviewerId))]
public ApplicationUser? Reviewer { get; set; }
```

关联字段还需要在 `ApplicationDbContext` 中检查外键和删除规则。

## 11. 已有数据时的注意事项

数据库已有数据时，不要直接增加一个没有默认值的必填字段。例如下面的写法可能导致迁移失败：

```csharp
public string MeetingLocation { get; set; }
```

更安全的做法是先允许为空：

```csharp
public string? MeetingLocation { get; set; }
```

如果业务要求最终必须填写，可以分三次处理：

1. 先新增可空字段。
2. 给历史数据补充内容。
3. 再生成一个迁移，把字段改成非空。

## 12. 重要规则

### 不要修改已经执行过的旧迁移

如果旧迁移已经在自己或服务器的数据库执行过，后续发现问题时，应重新创建一个新迁移进行修正。

### 不要只手工修改 MySQL

只手工修改 MySQL 会导致：

- 自己的数据库可以运行，其他开发人员无法运行。
- 服务器与代码结构不一致。
- 后续迁移可能失败。

### 不要只修改实体类

只修改实体类但不执行迁移，程序会尝试读取一个数据库中不存在的字段，从而出现“Unknown column”一类错误。

### 不要随意删除迁移文件

特别是已经提交或部署过的迁移。删除后，代码中的迁移记录将与数据库中的 `__EFMigrationsHistory` 不一致。

## 13. 开发前需要确认的需求

每次新增字段前，最好先明确：

- 字段属于哪个功能和数据表。
- 字段中文名称和英文名称。
- 字段类型是文字、数字、日期、人员还是选项。
- 是否必须填写。
- 最大长度是多少。
- 旧数据应该保持为空还是使用默认值。
- 哪些角色可以查看和修改。
- 新增、编辑、详情、列表中是否都要显示。
- 是否需要搜索、筛选、排序或建立索引。

确认这些内容后，再开始修改代码和生成数据库迁移。
