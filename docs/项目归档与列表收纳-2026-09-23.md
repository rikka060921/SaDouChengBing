# 项目归档与列表收纳

## 目标与边界

解决“旧项目占满日常列表”，同时避免只隐藏页面而后台继续写入。
本轮基于 GitHub main 的 08eebcd 开发，保留上轮 Agent 简化、授权、自动验收和可靠性逻辑。

| 状态 | 日常展示 | 业务推进 | 历史 |
| --- | --- | --- | --- |
| Active | 默认可见，仍受原权限控制 | 正常 | 可查看 |
| Archived | 从默认列表移出，在已归档/全部查找 | 停止新任务、会议、资料写入、正式 Agent 委托、普通催办 | 原权限下继续查看 |
| IsDeleted | 正常列表不可见 | 沿用原逻辑删除机制 | 本轮不开发回收站 |

归档不代表完成，不修改任务状态、进度、验收结果或完成率。保留原实体字段；数据库迁移数量：0。

## 页面行为

- /Projects 默认“活跃项目”；提供“已归档”“全部”三个状态视图。“全部”不是全部数据库记录，只是当前用户可见且未删除的项目。
- 搜索、每页数量、分页保留视图，链接使用路由编码，支持包含 & 的关键词；重置回到活跃视图。超出末页会回到有效页码。
- 归档前读取检查结果。未结束工作会显示原因；普通未完成任务显示数量，用户明确确认后才能归档。POST 再检查，不能绕过确认与权限。
- 成功后重新加载当前查询，重新计算数量、分页和权限，不在浏览器手拼操作菜单。
- 项目导航显示归档只读提示；归档任务的编辑/进展/验收/评论、资料上传等主要操作禁用或隐藏，直接提交仍由服务端拒绝。
- 创建会议、报告、会前准备、正式 Agent 运行的项目选择过滤归档项目。历史查询仍可选择旧项目；会议历史选项标注“已归档”。
- 多项目会议只要任一关联项目不可写，拒绝新建/修改。新建纪要和全部项目关联在同一事务中保存，避免半条记录。

## 归档前检查

ProjectLifecycleRules.CheckArchiveAsync 汇总阻塞原因，ProjectDomain 在具备原管理权限后执行状态转换。

阻止归档：

- AgentWorkItem 的 Pending、Running、Retrying、Paused、WaitingApproval、WaitingPlanConfirmation。
- 手工 Agent 运行及事件执行中的排队、运行、重试、等待审批。
- Pending/Processing 审批、PendingApproval 工具调用。
- 人工或 AI 任务处于 PendingConfirmation。
- 本项目定时作业正在执行。

已经 Completed/Failed/Cancelled 的历史 Agent 工作不单独阻止归档。
普通未完成任务允许确认后归档；失败记录仍可从历史/管理入口查看。
不提供“强制归档并自动暂停一切”的隐藏操作。

## 写入与并发防线

1. Domain 层在文件写入、正式入队、工具执行、审批实际执行及任务推进前检查活跃状态。管理员同样不能直接向归档项目写业务数据。
2. ApplicationDbContext 的 ProjectWriteGuard 是最后防线，覆盖任务/标签/分组/评论、会议及关联/版本/附件/行动项、准备草稿、报告及附件、资料/分类/AI 草稿、成员新增或提权、队列新增等跟踪写入。
3. 间接实体沿 TaskId、MeetingMinutesId、DailyReportId 等查找所属项目；同时检查原项目和新项目，不能通过“把旧任务移到活跃项目”绕过。多项目会议检查完整关联。
4. 不设置全局 Active 查询过滤器，避免把历史记录和关联隐藏掉。
5. 操作日志、通知、AI 历史消息、索引派生数据以及必要的权限撤销仍可写。成员移除/降权不因归档受阻。项目业务内容只读。
6. MySQL 保存时在当前事务内按项目 ID 顺序锁定项目行；归档转换使用 Serializable 事务，减少“检查之后、写入之前”的竞态。锁定读取使用当前状态，避免重复读快照误判。
7. ExecuteUpdate 等绕过跟踪器的队列领取/恢复路径另加活跃状态条件。新增类似批量写入时，必须同步补归档条件与回归测试。
8. 未被页面自行处理的只读写入异常返回 HTTP 400 和可读原因，不暴露异常堆栈或变成通用 500。

生命周期不是工具权限。Agent 的 project.update 不再允许顺带改变项目状态；必须走项目列表的归档/恢复检查与确认。现有项目业务编辑工具仍保留。

## 自动化与恢复

- 正式 Agent 工作在入队、领取、执行及恢复环节检查项目；归档项目不自动补建工作项。实际写入工具和审批执行再次检查。
- 存量异常情况下，已运行的正式工作遇到归档会暂停/终止当前推进并保留原因，不偷偷写入或自行完成任务。
- 事件分发仍消费消息并记录 Skipped，不能反复留在 Pending 造成忙循环。
- 专属定时作业在归档时安全跳过，由原调度器推进下一次运行；全局日报继续只选 Active 项目。
- 普通逾期提醒、会议督办、日常待办不再催促已归档业务。没有批量清空旧通知，也没有把审批、安全异常、失败处理全部隐藏。
- 恢复时推进项目摘要水位和专属定时作业的下一次执行时间，并写入现有活动日志中的 AutomationResumeBoundary。
- 早于恢复边界的事件不补跑；旧待派单/待补建任务不会仅因恢复而重新触发。
- 对旧版本遗留的异常未结束队列，恢复时保留记录并取消/跳过，不自动续跑；任务本身状态与进度不变。需要继续时重新委托。
