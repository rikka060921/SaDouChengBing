# 生产就绪与运维指南

本文是当前版本的上线最低基线。目标不是“服务能启动”，而是 Agent 的派单、执行、审批、交付和验收链路在故障、篡改、扩容与回滚时仍然可解释、可恢复。

## 一、发布前必须完成

1. 备份 MySQL 数据库并验证备份能够恢复。
2. 使用独立的 `todo_app` 数据库账号，不使用 `root`。账号只授予本应用库所需的 DDL/DML 权限；迁移完成后可进一步拆分迁移账号与运行账号。
3. 通过服务器环境变量或密钥管理服务注入配置，不把密码、模型 Key、签名密钥写入仓库或发布包。
4. 先执行 Release 构建、全部测试和发布产物检查，再切换 IIS 站点。
5. 发布后依次检查 `/health/live`、`/health/ready`、管理员 `/SystemHealth`，最后执行本文的业务冒烟用例。

生产环境必填配置：

```text
ASPNETCORE_ENVIRONMENT=Production
ConnectionStrings__DefaultConnection=server=...;database=todo123;user=todo_app;password=...;CharSet=utf8mb4;SslMode=Required
AI__ApiKey=...
Security__IntegritySigning__CurrentKeyId=v1
Security__IntegritySigning__CurrentKey=<32字节以上随机值的Base64>
```

PowerShell 生成 32 字节随机签名密钥：

```powershell
[Convert]::ToBase64String([Security.Cryptography.RandomNumberGenerator]::GetBytes(32))
```

生产模式未提供有效签名密钥时，应用会拒绝启动。这是有意的失败关闭策略，防止新审批和交付继续以无密钥哈希形式产生。

## 二、审批和交付签名

新审批载荷与 Agent 交付凭证先计算规范化 SHA-256，再使用服务端 HMAC-SHA256 签名。界面同时校验“内容哈希”和“服务签名”，任一失败都视为异常；审批执行会直接拒绝被篡改的载荷。

历史数据在迁移时标记为 `legacy-hash-only`，仍可按原哈希检查内容是否变化，但不会伪装成已经使用服务密钥签名。生产环境不会执行未签名的历史待审批请求；上线前应撤销这些请求，并由原 Agent 在新版本重新发起。

密钥轮换步骤：

1. 保留旧密钥，并生成新密钥和新 KeyId。
2. 设置 `Security__IntegritySigning__PreviousKeys__v1=<旧密钥>`。
3. 将 `CurrentKeyId` 改为 `v2`，将 `CurrentKey` 改为新密钥后发布。
4. 确认历史凭证仍显示有效、新凭证使用 `v2`。
5. 只有超过业务审计保留期后，才可移除旧密钥。

不要复用数据库密码、AI Key 或 ASP.NET Data Protection Key 作为签名密钥。

## 三、Agent 可观测性

系统提供两个标准观测入口：

- ActivitySource/Meter 名称：`SaDouChengBing.AgentAutomation`。
- 指标：`agent.jobs.queued`、`agent.attempts.succeeded`、`agent.attempts.failed`、`agent.queue.wait`、`agent.execution.duration`。
- Trace 标签：队列类型、工作项/运行任务 ID、项目 ID、任务 ID。
- `/health/ready`：数据库不可用返回 503；公开响应不暴露内部队列数量。
- `/SystemHealth`：仅系统管理员可见，展示待执行队列、超时执行锁、待审批和待验收数量。

部署 OpenTelemetry Collector 时订阅上述源即可，不需要修改业务代码。建议至少配置以下告警：数据库就绪失败、超时执行锁大于 0、失败率连续升高、P95 排队时间异常、待人工审批/验收长期增长。

## 四、数据留存

默认配置：

```json
{
  "DataRetention": {
    "Enabled": false,
    "ArchiveAiSessionsAfterDays": 180,
    "DeleteReadNotificationsAfterDays": 90,
    "BatchSize": 500,
    "RunIntervalHours": 24
  }
}
```

默认不自动执行。管理员先在 `/DataGovernance` 预览影响数量，勾选确认后按批次执行。策略只做两件事：

- 将超过保留期且已结束/失败/取消的 AI Session 标为归档；归档数据仍可查看。
- 删除超过保留期且已经读取的通知。

Agent 交付凭证、审批、工具调用、验收建议、会议督办事件、操作日志均不会被本策略删除。每次执行会写入 `data_retention_runs`，记录触发人、阈值、数量、状态和异常。确认策略稳定后，才把 `DataRetention__Enabled` 设置为 `true`。

## 五、CSP 与浏览器安全

服务端为每个响应生成随机 nonce，自动附加到 Razor 输出的 `<script>` 和 `<style>` 元素。CSP 已禁止普通内联脚本/样式元素；旧页面仍有内联 DOM 事件属性，因此暂时保留 `script-src-attr 'unsafe-inline'` 和 `style-src-attr 'unsafe-inline'` 的兼容边界。

后续新增页面不得继续添加 `onclick`、`onchange`、`style="..."` 等属性，应使用外部脚本的事件绑定和 CSS class。待历史页面完成机械迁移后，再删除 CSP 的 attr 兼容项。

## 六、发布后冒烟验收

1. 以普通成员创建一条具有项目、风险和截止时间的任务，不选择数字员工。
2. 确认调度器自动选择 Agent；低置信度任务进入“待我处理”，高置信度任务自动入队。
3. 打开 Agent 执行详情，确认版本号、队列状态、执行步骤和 Session 可追踪。
4. 触发低风险只读工具，确认自动执行；触发高风险写入工具，确认进入审批且未经审批不会回写。
5. 审批后确认原工作自动恢复，不需要再次手工点击运行。
6. Agent 完成后确认任务进入“待确认”，生成交付凭证、结构化验收建议和有效签名；人工通过或打回后状态正确回写。
7. 从会议纪要原话跳转到行动项/任务，检查未关联、临期、逾期和阻塞提醒是否进入督办中心。
8. 重启服务，确认运行中的任务被释放为重试、已完成任务不重复执行、同一提醒不会重复发送。

## 七、回滚边界

应用文件可切回上一 Release；数据库迁移不能靠切回文件自动撤销。本次迁移只增加签名字段、Session 归档字段、索引和留存执行表，不删除历史数据。若应用回滚，保留新增字段不会影响上一版本；不要在事故处理中直接执行 `database update <旧迁移>`，应先恢复发布前备份或经过审查的前向修复迁移。
