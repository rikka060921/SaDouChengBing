# Agent 简化说明

## 本轮范围

依据 2026 年 9 月 3 日会议总结的后半段意见，并按本次确认范围实施：
取消前置综合评分，按用途和注册职责匹配；取消日常管理中的独立发布操作；
保留项目和资料权限、工具审批、人工验收、历史配置及运行记录。
联网搜索、任务规划和新增多 Agent 协作不在本轮范围。

## 用户现在怎么操作

1. 创建任务，将执行主体设为数字员工。
2. 系统按用途规则识别任务方向，在已启用、允许接单的 Agent 中匹配注册能力标签。
3. 唯一匹配自动进入持久化执行队列；多个匹配由人明确选择；没有匹配提示修改任务、检查授权或改为人工。
4. 在任务详情看交付，在待我处理完成执行者选择、工具审批和交付验收。
5. Agent 仍不允许自行通过人工验收，高风险工具仍强制人工审批。

当前用途识别采用明确规则与能力值匹配，不调用大模型打分，也不把关键词匹配包装成模型置信度。
常见用途包括任务进度分析、风险复核、会议整理、日报周报、资料整理，以及已有受控写入工具。
无法识别、复合任务缺少某项能力、所需工具未启用、资料未授权时，不强行选用通用 Agent。
能力标签不是权限授权。未知用途可先改写任务描述，或改为人工。

## 管理员现在怎么配置

- 新建或编辑 Agent，配置职责、能力标签、上下文和工具。
- 保留每个 Agent 的模型选择；高级模型参数和交付测试设置默认折叠。
- 保存配置后按启用开关生效，不再强制先隔离测试再点发布。
- 隔离测试作为可选质量诊断，仍关闭业务工具；测试结果不等同人工验收。
- 当前配置的测试不会自行启用已停用 Agent，也不会因输出测试失败停用已启用 Agent。
- 配置历史继续留存，旧会话引用的历史版本不会被新配置覆盖。
- 历史发布、灰度接口暂留作兼容，已从默认管理页面移除，不清理历史业务数据。

## 调度与数据边界

- 删除能力、权限、风险、负载、历史表现的加权排序，以及前置置信度阈值。
- 多候选按注册顺序列出，不暗示第一位更优秀，不预选最高分。
- 质量、费用及人工选择继续记录，但不参与前置派单评分。
- 确认执行者时重新检查当前职责与项目授权，拒绝已撤销权限的旧候选。
- 无匹配的待办也进入待我处理；旧版本、已删除、已完成、已取消任务的匹配待办不再展示。
- 沿用原有派单唯一索引和幂等队列，不新增数据库迁移。

## 验收清单

1. 仅启用一个职责匹配的 Agent，创建对应任务，确认自动入队。
2. 启用两个相同职责的 Agent，确认显示候选选择而不是分数；明确选择后仅入队一次。
3. 创建未知用途任务，确认没有强行执行，可从待我处理进入任务调整。
4. 配置资料助手但不给项目资料读取权限，确认不会自动匹配；授权后重新保存任务再匹配。
5. 能力标签声明可写资料但缺少写工具或资料写权限，确认不自动派单。
6. 待确认后撤销资料授权，确认旧候选被拒绝。
7. 注册启用一个未经隔离测试的 Agent，确认可使用，但高风险工具仍需要人工审批。
8. 停用 Agent 后运行可选测试，确认不会自动重新启用。
9. 编辑配置后核对历史快照，确认旧版本仍保留。
10. 确认页面默认没有发布/灰度按钮，高级设置可展开。
