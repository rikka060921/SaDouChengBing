1. 会议纪要不只是“总结换位置”，而是要拆成两个页面：

   - 会前简报：上次会议摘要、行动项、全部未完成任务及状态。放在项目管理、项目详情之下。

   - “会议准备”页面内容

     页面只负责会前查看，不负责创建纪要：

     1. 上次会议摘要
     2. 上次会议行动项
     3. 全部未完成任务
     4. 任务负责人、截止时间、当前状态
     5. 逾期和即将到期任务
     6. “新建本次会议纪要”按钮

   - ```
     项目管理
     └── 项目详情
         ├── 项目概览
         ├── 任务
         ├── 项目资料
         ├── 会议准备
         └── 会议纪要
     ```

   - 新建会议纪要：只负责录入、编辑、保存本次会议。

   - 原文默认折叠，通过“展开原文”按钮查看。

   - 保留手动选择实际会议日期，不能用导入日期推算。

2. 二级菜单应有明确交付物：

   - 左侧导航，任务看板为默认首页。
   - 输出菜单结构表：一级菜单、二级菜单、页面路由、访问角色、跳转关系。
   - 先确定结构和权限，再改页面，不应只写“解决逻辑跳转问题”。

3. 通知机制要写成规则表，而非泛泛“细化需求”：

   - 事件通知：触发事件、接收人、即时发送条件。
   - 提醒通知：提醒对象、首次提醒时间、重复频率、停止条件。
   - 已读/未读、一键已读、紧急程度。
   - 页面内操作失败只做即时提示，不重复进入消息中心。

4. 每日工作汇总需要明确“变更”的判断依据：

   - 上次日报后任务创建、状态/负责人/截止日期变化。
   - 会议纪要新增或更新。
   - 项目资料或其他纳入汇总的数据发生变化。
   - 无变更则不调用 AI、不创建新日报；需要保存每项目上次成功汇总时间。

5. 任务模块建议改为：

   - 子任务：放在任务描述下方。
   - 评论：独立一行，放在详情页底部。
   - 操作日志：不再放在任务详情页底部，保留在全局操作日志页面；任务详情页提供“查看该任务日志”链接，并按任务 ID 筛选。
   - 指派人支持人员和 Agent，页面直接显示执行主体。
   - 多项目负责人均可作为审核人，这条也应写入规则。

6. Agent 和红蓝对抗还应补充：

   - 红蓝对抗的“主持人”不是只确认主题，还要读取任务信息，生成主题、目标和辩论轮数。
   - Agent 中心增加会话/执行日志详情按钮，查看输入、输出、调用参数和失败原因。
   - Agent 不能继续只靠硬编码注册；智能体框架需支持工具调用、读取数据和多轮执行。
   - 红蓝对抗结果及其他 Agent 产物应能写回任务或项目资料。

7. 项目资料模块要补全：

   - 资料分类。
   - Agent 按分类读取资料。
   - 数据收集类 Agent 可写入资料。
   - 明确哪些 Agent 可读、可写哪些分类，避免所有 Agent 无限制访问。
