# ToDo项目权限控制问题分析报告

## 权限控制实现情况

### 1. 用户和角色管理
- 项目实现了基于角色的访问控制（RBAC），在`ApplicationUser`实体中定义了三种用户角色：系统管理员（Admin）、项目管理员（ProjectAdmin）、项目成员（RegularUser）
- 系统管理员拥有最高权限，可以管理所有用户和项目
- 项目管理员可以管理自己负责的项目及其相关资源
- 项目成员可在所属项目内执行任务相关操作
- 通过`[Authorize(Roles = "Admin")]`特性限制了用户管理页面的访问权限
- 系统初始化时在`SeedData.cs`中创建了两个管理员账户（admin@example.com和GZY）

### 2. 项目管理权限
- 项目创建者自动成为项目管理员
- 只有项目管理员或系统管理员可以归档/恢复项目
- 项目列表页面实现了权限控制，项目成员只能看到自己参与的项目

### 3. 会议纪要管理权限
- 创建者48小时内可编辑/删除会议纪要
- 项目管理员可删除所管理项目的会议纪要
- 系统管理员可删除任何会议纪要
- 创建时正确设置了创建者ID

### 4. 日报管理权限
- 创建者24小时内可修改日报
- 项目管理员和系统管理员可查看所有人的日报
- 项目成员仅能查看自己的日报
- 创建时正确设置了创建者ID

### 5. 用户管理权限
- 用户创建、编辑、删除等功能仅限系统管理员访问

## 存在的问题

### 1. 硬编码用户ID
- 在`TaskGroups/Edit.cshtml.cs`和`Tasks/Edit.cshtml.cs`中，使用了硬编码的`currentUserId = "user1-id"`，这会导致所有任务和任务分组都关联到同一个用户

### 2. 缺少项目成员管理
- 虽然数据库设计中包含了`ProjectUser`实体来表示项目成员关系，但在业务逻辑中没有实现相关的权限控制
- 项目中的任务、任务分组等资源没有基于项目成员权限进行访问控制
- `ProjectDomain`类中没有实现添加/移除项目成员的方法
- 缺少项目成员管理功能，无法通过界面添加或移除项目成员

### 3. 任务管理权限不完善
- 任务编辑页面没有实现权限控制，任何用户都可以编辑任何任务
- 没有基于项目成员身份的任务访问控制

### 4. 任务分组管理权限不完善
- 任务分组编辑页面没有实现权限控制，任何用户都可以编辑任何任务分组
- 没有基于项目成员身份的任务分组访问控制

### 5. 会议纪要权限控制不完整
- 未实现项目成员创建会议纪要的权限控制
- 未实现项目成员查看所属项目会议纪要的权限控制

### 6. 日报权限控制不完整
- 未实现项目成员提交日报的权限控制
- 未实现日报查看权限的严格控制

### 7. 缺少基于策略的授权实现
- 虽然设计文档中提到了基于策略的授权（如`ProjectAdminRequirement`和`ProjectAdminPolicy`），但在代码中未找到相关实现
- 项目管理员的权限控制依赖于在各个页面中手动检查用户是否为项目创建者，而不是通过统一的策略授权机制

### 8. 基于策略的授权实现不完整
- 缺少`ProjectAdminRequirement`和`ProjectAdminPolicy`的具体实现代码
- 设计文档中提到了基于策略的授权，但实际代码中未找到相关实现

## 改进建议

### 1. 修复硬编码用户ID问题
- 在`TaskGroups/Edit.cshtml.cs`和`Tasks/Edit.cshtml.cs`中，应从当前登录用户获取用户ID，而不是使用硬编码值

### 2. 实现项目成员管理功能
- 在项目Domain层添加管理项目成员的方法
- 实现添加/移除项目成员的功能
- 在项目成员管理中支持设置项目管理员权限

### 3. 完善任务管理权限控制
- 在任务编辑页面添加权限验证，确保只有创建者、项目管理员或系统管理员可以编辑任务
- 实现基于项目成员身份的任务访问控制

### 4. 完善任务分组管理权限控制
- 在任务分组编辑页面添加权限验证，确保只有创建者、项目管理员或系统管理员可以编辑任务分组
- 实现基于项目成员身份的任务分组访问控制

### 5. 完善会议纪要权限控制
- 实现项目成员创建会议纪要的权限控制
- 实现项目成员查看所属项目会议纪要的权限控制
- 实现创建者48小时内编辑/删除、项目管理员删除、系统管理员删除的权限控制

### 6. 完善日报权限控制
- 实现项目成员提交日报的权限控制
- 实现日报创建者24小时内修改、管理员查看所有、成员查看自己的权限控制

### 7. 实现基于策略的授权
- 创建`ProjectAdminRequirement`类继承`IAuthorizationRequirement`
- 实现`ProjectAdminRequirementHandler`继承`AuthorizationHandler<ProjectAdminRequirement>`，注入`ProjectDomain`来判断用户是否为项目管理员
- 在`Program.cs`中配置`ProjectAdminPolicy`策略
- 在需要项目管理员权限的页面或API中使用`[Authorize(Policy = "ProjectAdminPolicy")]`特性

### 8. 增强权限控制的统一性
- 考虑创建统一的权限验证服务，避免在各个页面中重复实现权限检查逻辑
- 使用自定义授权策略来处理复杂的权限验证逻辑
