## 使用中发现并修正的问题

### 1. 执行成员无法推进负责人创建的任务

原先完整编辑权限仅对创建者或项目管理者开放，普通被指派成员虽然能阅读、评论，却不能更新进度或提交验收。

新增“我的执行进展”，通过 `TaskProgressService` 限定能力：

- 仅本人负责的、当前仍可执行的人工任务可更新；只有未指派时才回退到认领人。
- 后端检查账号启用状态、当前项目成员资格、项目/任务是否删除、任务状态及执行主体。
- 不开放改派、修改任务要求、修改项目等完整编辑权限。
- 保存进展不会产生额外通知；提交验收必须填写成果和核验说明，仅提醒实际审核人，必要时回退项目管理者。
- 提交验收后为待验收状态，进度 99%；沿用原有审核规则，通过后才是 100%。本次没有给 AI 自动执行任务增加人工审批步骤。
- 进展说明、状态、操作日志、验收提醒一次保存；无有效审核人时不会暂存半条提交。
- 使用任务并发版本拒绝旧页面覆盖；失败保留说明，提供 GET 重新读取最新状态的链接，避免浏览器刷新重放旧表单。

### 2. 没有提醒容易被误认为没有工作

首页增加“我负责的工作”计数与入口；列表增加“我的进行中任务”范围。没有紧急提醒不等于没有任务。

个人范围仅显示本人仍需推进的人工任务，待验收与已完成任务不混入；空列表说明如何查看已提交和已完成工作。普通进展不因此变成一条条催办通知。

### 3. 从项目直接新建会议，简报停在加载中

真实页面复现 JavaScript 错误：`Cannot access 'briefingRequestId' before initialization`。

将请求计数器移至初始项目回显之前。清空项目时同步清空简报和计数，并让尚未返回的请求失效；通过延迟真实简报响应验证，不会在取消选择后重新显示旧内容。

项目名称插入提示 HTML 前增加转义；浏览器验证 `<img ...>` 显示为字面文本，不创建图片元素或执行事件。

### 4. 分工和个人任务识别细节

任务负责人/审核人选项显示真实姓名与账号，列表优先显示真实姓名；选择框排除停用账号。进展输入限制 0—99%，成果说明限制 1500 字。手机端检查 390px 宽度及实际截图，新入口和 AI 协助区没有横向溢出。

## 验证边界

- MySQL 是本轮新初始化的独立本地实例（仅监听 127.0.0.1:33319，独立 `team_sim` 数据库），页面宿主仅监听 127.0.0.1:5202。没有连接原业务数据库或线上站点。
- AI 和会议解析返回明确标记的本地模拟结果。真实验证的是权限、请求、队列处理、结果存储、页面刷新和协作状态流转，不是模型推理质量、真实语音转写或联网搜索效果。
- 本轮跑通的是任务内只读 AI 协助队列；不能据此声称正式数字员工自动调度、自动执行、自动验收的整条生产链路已完成本轮端到端验证。
- 新数据库初始化成功不等于现有服务器数据库升级已经验证；本轮没有新增数据库字段或迁移。
- 完成后的行动中心卡片会自动移出；历史通知记录仍保留，不等同于删除历史消息。
- 测试项目只存在于隔离实例，不会随 Git 推送自动出现在服务器。运行证据和隔离数据保留在本地，不应把测试账号状态文件或数据目录提交进 Git。

结论：本轮补齐了小团队成员自主推进工作的实际断点，减少了负责人代改进度和代提交的工作；不是对整个产品作“没有任何问题”的保证。
