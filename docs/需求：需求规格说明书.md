# 需求：ToDo项目管理系统需求规格说明书

## 1. 引言

### 1.1 目的

本文档旨在**精确描述** ToDo 项目管理系统应满足的功能和非功能需求，作为系统开发、测试和验收的依据。本文档是**需求规格化阶段**的输出物，侧重于"定义明确、可验证的需求"。

本文档中的每项需求均应具备：
- **完整性**：需求描述无遗漏
- **一致性**：与其他需求无冲突
- **可验证性**：可通过测试验证是否满足
- **可追踪性**：可追溯到用户需求来源

### 1.2 范围

本文档定义系统的完整功能范围，包括：
- 用户与权限管理
- 项目管理
- 任务管理
- 分组管理
- 操作日志管理
- 会议纪要管理
- 日报管理
- AI智能服务
- 数据统计与报表

### 1.3 术语与缩略语

| 术语 | 定义 |
|-----|------|
| CRUD | Create, Read, Update, Delete（增、查、改、删） |
| API | Application Programming Interface，应用程序编程接口 |
| UI | User Interface，用户界面 |

## 2. 总体描述

### 2.1 系统架构

系统采用分层架构设计，包含以下层次：

| 层次 | 名称 | 职责 |
|-----|------|------|
| 表现层 | ToDo.Razor | 用户界面展示、请求接收、数据绑定 |
| 业务逻辑层 | ToDo.Domain | 核心业务规则、流程处理、权限判断 |
| 数据访问层 | ToDo.Context | 数据库交互、EF Core 映射配置 |
| 实体层 | ToDo.Entities | 数据实体模型定义 |
| 数据库层 | MySQL 8 | 数据持久化存储 |

### 2.2 技术栈

| 组件 | 技术选型 | 版本要求 |
|-----|---------|---------|
| 框架 | ASP.NET Core | 8.0 |
| ORM | Entity Framework Core | 8.x |
| 数据库 | MySQL | 8.0+ |
| UI框架 | Razor Pages | - |
| 认证 | ASP.NET Core Identity | - |
| AI服务 | OpenAI 兼容 API | - |

### 2.3 角色定义

#### 2.3.1 系统级角色

| 角色标识 | 角色名称 | 权限范围 |
|---------|---------|---------|
| systemAdmin | 系统管理员 | 系统全局 |
| teamMember | 团队成员 | 系统全局 |

#### 2.3.2 项目级角色

| 角色标识 | 角色名称 | 权限范围 |
|---------|---------|---------|
| ProjectRole.Admin | 项目管理员 | 特定项目内 |
| ProjectRole.Member | 项目成员 | 特定项目内 |

## 3. 功能需求

### 3.1 用户与权限模块

#### FR-USER-001: 用户登录
- **描述**: 用户通过用户名和密码登录系统
- **前置条件**: 用户账号存在且状态为激活
- **输入**: 用户名、密码
- **输出**: 登录成功则跳转首页，失败则显示错误信息
- **优先级**: P0
- **验收标准**:
  - [ ] 输入正确凭据后成功登录
  - [ ] 输入错误密码显示"用户名或密码错误"
  - [ ] 禁用用户无法登录，显示"账号已被禁用"

#### FR-USER-002: 用户登出
- **描述**: 终止当前用户会话
- **前置条件**: 用户已登录
- **输出**: 跳转至登录页面
- **优先级**: P0
- **验收标准**:
  - [ ] 点击登出后清除会话
  - [ ] 跳转至登录页面

#### FR-USER-003: 用户创建
- **描述**: 系统管理员创建新用户账号
- **前置条件**: 操作者具有 systemAdmin 角色
- **输入**: 用户名、密码、初始角色(可选，默认 teamMember)
- **输出**: 创建成功返回用户列表页
- **业务规则**: 
  - 用户无法自行注册
  - 用户名不可重复
- **优先级**: P0
- **验收标准**:
  - [ ] 系统管理员可创建用户
  - [ ] 普通用户无法创建用户
  - [ ] 用户名重复时提示错误

#### FR-USER-004: 用户列表查看
- **描述**: 系统管理员查看所有用户列表
- **前置条件**: 操作者具有 systemAdmin 角色
- **输入**: 筛选条件(可选): 用户状态
- **输出**: 用户列表页面
- **优先级**: P0
- **验收标准**:
  - [ ] 显示所有用户信息
  - [ ] 可按状态筛选

#### FR-USER-005: 用户状态管理
- **描述**: 系统管理员禁用或激活用户账号
- **前置条件**: 操作者具有 systemAdmin 角色，且不可操作自己
- **输入**: 目标用户ID、目标状态(激活/禁用)
- **输出**: 操作成功提示
- **业务规则**: 禁用用户无法登录
- **优先级**: P0
- **验收标准**:
  - [ ] 可禁用用户
  - [ ] 可激活用户
  - [ ] 禁用后用户无法登录
  - [ ] 不可禁用自己

#### FR-USER-006: 用户删除(软删除)
- **描述**: 系统管理员删除用户(逻辑删除)
- **前置条件**: 操作者具有 systemAdmin 角色
- **输入**: 目标用户ID
- **输出**: 操作成功提示
- **业务规则**: 
  - 执行软删除，IsDeleted 设为 true
  - 删除后用户无法登录
  - 用户数据保留
- **优先级**: P1
- **验收标准**:
  - [ ] 删除后用户无法登录
  - [ ] 用户数据仍存在于数据库

#### FR-USER-007: 用户恢复
- **描述**: 系统管理员恢复已删除用户
- **前置条件**: 操作者具有 systemAdmin 角色
- **输入**: 目标用户ID
- **输出**: 操作成功提示
- **业务规则**: 恢复后用户可重新登录
- **优先级**: P1
- **验收标准**:
  - [ ] 恢复后用户可登录

#### FR-USER-008: 角色分配
- **描述**: 系统管理员为用户分配系统角色
- **前置条件**: 操作者具有 systemAdmin 角色
- **输入**: 目标用户ID、新角色
- **输出**: 操作成功提示
- **优先级**: P1
- **验收标准**:
  - [ ] 可将用户设为 systemAdmin
  - [ ] 可将用户设为 teamMember

#### FR-USER-009: 个人资料查看
- **描述**: 用户查看自己的个人信息
- **前置条件**: 用户已登录
- **输出**: 显示用户名、邮箱、手机号、真实姓名等信息
- **优先级**: P1
- **验收标准**:
  - [ ] 显示当前用户信息

#### FR-USER-010: 个人资料更新
- **描述**: 用户更新自己的个人信息
- **前置条件**: 用户已登录
- **输入**: 真实姓名、性别、手机号、头像URL(可选)
- **输出**: 更新成功提示
- **业务规则**: 不可修改用户名和邮箱
- **优先级**: P1
- **验收标准**:
  - [ ] 可更新个人资料
  - [ ] 不可修改用户名和邮箱

### 3.2 项目管理模块

#### FR-PROJ-001: 项目创建
- **描述**: 系统管理员创建新项目
- **前置条件**: 操作者具有 systemAdmin 角色
- **输入**: 项目名称、项目描述(可选)、项目需求(可选)
- **输出**: 创建成功返回项目详情页
- **业务规则**:
  - 项目创建者自动成为项目负责人
  - 项目创建者自动成为项目管理员(ProjectRole.Admin)
  - 项目状态默认为 Active
- **优先级**: P0
- **验收标准**:
  - [ ] 系统管理员可创建项目
  - [ ] 创建者自动成为负责人
  - [ ] 创建者自动成为项目管理员

#### FR-PROJ-002: 项目列表查看
- **描述**: 用户查看有权限访问的项目列表
- **前置条件**: 用户已登录
- **输入**: 筛选条件(可选): 项目名称、创建人、状态
- **输出**: 项目列表页面
- **业务规则**:
  - systemAdmin 可查看所有项目
  - 其他用户仅查看其参与的项目
- **优先级**: P0
- **验收标准**:
  - [ ] 显示有权限访问的项目
  - [ ] 可按名称/创建人/状态筛选

#### FR-PROJ-003: 项目详情查看
- **描述**: 用户查看项目详细信息
- **前置条件**: 用户有权限访问该项目
- **输入**: 项目ID
- **输出**: 项目详情页面，包含:
  - 项目基本信息
  - 任务统计(总数/进行中/已完成)
  - 项目成员列表
- **优先级**: P0
- **验收标准**:
  - [ ] 显示项目完整信息
  - [ ] 显示任务统计
  - [ ] 显示成员列表

#### FR-PROJ-004: 项目编辑
- **描述**: 修改项目信息
- **前置条件**: 操作者具有项目 Admin 角色或 systemAdmin 角色
- **输入**: 项目ID、项目名称、项目描述(可选)、项目需求(可选)
- **输出**: 操作成功提示
- **优先级**: P1
- **验收标准**:
  - [ ] 项目管理员可编辑项目
  - [ ] 系统管理员可编辑任何项目

#### FR-PROJ-005: 项目归档
- **描述**: 将项目归档
- **前置条件**: 操作者具有项目 Admin 角色或 systemAdmin 角色
- **输入**: 项目ID
- **输出**: 操作成功提示
- **业务规则**:
  - 归档后项目状态变为 Archived
  - 归档项目不显示在活跃项目列表中
  - 归档后可恢复
- **优先级**: P1
- **验收标准**:
  - [ ] 可将项目归档
  - [ ] 归档后不显示在活跃列表
  - [ ] 可恢复归档项目

#### FR-PROJ-006: 项目成员添加
- **描述**: 向项目中添加成员
- **前置条件**: 操作者具有项目 Admin 角色或 systemAdmin 角色
- **输入**: 项目ID、用户ID、角色(Admin/Member)
- **输出**: 操作成功提示
- **业务规则**:
  - 同一用户不可重复加入同一项目
  - 系统管理员可为任何项目添加成员
  - 项目管理员仅能为所属项目添加成员
- **优先级**: P0
- **验收标准**:
  - [ ] 可添加项目成员
  - [ ] 不可重复添加同一成员

#### FR-PROJ-007: 项目成员移除
- **描述**: 从项目中移除成员
- **前置条件**: 操作者具有项目 Admin 角色或 systemAdmin 角色
- **输入**: 项目ID、用户ID
- **输出**: 操作成功提示
- **业务规则**:
  - 不可移除项目创建者
  - 项目管理员不可移除自己
- **优先级**: P1
- **验收标准**:
  - [ ] 可移除项目成员
  - [ ] 不可移除创建者
  - [ ] 管理员不可移除自己

#### FR-PROJ-008: 项目负责人更换
- **描述**: 更换项目负责人
- **前置条件**: 操作者为 systemAdmin 或项目负责人
- **输入**: 项目ID、新负责人用户ID
- **输出**: 操作成功提示
- **业务规则**: 新负责人必须是项目成员
- **优先级**: P1
- **验收标准**:
  - [ ] 可更换项目负责人
  - [ ] 新负责人必须是项目成员

#### FR-PROJ-009: 项目可见性设置
- **描述**: 设置项目可见性
- **前置条件**: 操作者具有项目 Admin 角色或 systemAdmin 角色
- **输入**: 项目ID、可见性设置(0-公开/1-成员可见/2-仅负责人可见)
- **输出**: 操作成功提示
- **优先级**: P2
- **验收标准**:
  - [ ] 可设置项目可见性

#### FR-PROJ-010: 项目统计
- **描述**: 显示项目统计信息
- **前置条件**: 用户有权限访问该项目
- **输出**: 任务总数、进行中任务数、已完成任务数、项目进度百分比
- **业务规则**: 项目进度 = 已完成任务数 / 任务总数 × 100%
- **优先级**: P1
- **验收标准**:
  - [ ] 显示任务总数
  - [ ] 显示进行中任务数
  - [ ] 显示已完成任务数
  - [ ] 显示项目进度百分比

### 3.3 任务管理模块

#### FR-TASK-001: 任务创建
- **描述**: 在项目中创建新任务
- **前置条件**: 操作者为项目成员
- **输入**:
  - 项目ID
  - 任务标题(必填,最大255字符)
  - 任务描述(可选,支持Markdown)
  - 所属分组ID(可选)
  - 优先级(High/Medium/Low,默认Medium)
  - 初始状态(默认NotStarted)
  - 开始时间(可选)
  - 截止时间(可选)
- **输出**: 创建成功返回任务详情页
- **业务规则**:
  - 创建者自动成为任务责任人
  - 任务默认属于"未分组"
- **优先级**: P0
- **验收标准**:
  - [ ] 可创建任务
  - [ ] 创建者自动成为责任人
  - [ ] 支持Markdown格式

#### FR-TASK-002: 任务列表查看
- **描述**: 查看任务列表
- **前置条件**: 操作者为项目成员
- **输入**: 筛选条件(可选): 所属项目、所属分组、任务状态、指派人、认领人、优先级
- **输出**: 任务列表页面
- **优先级**: P0
- **验收标准**:
  - [ ] 显示任务列表
  - [ ] 支持多维度筛选

#### FR-TASK-003: 任务详情查看
- **描述**: 查看任务详细信息
- **前置条件**: 操作者有权限访问该任务
- **输入**: 任务ID
- **输出**: 任务详情页面，包含:
  - 任务标题、描述
  - 所属项目、所属分组
  - 任务状态、优先级、进度
  - 指派人、认领人
  - 开始时间、截止时间
  - 变更日志摘要列表
- **优先级**: P0
- **验收标准**:
  - [ ] 显示任务完整信息
  - [ ] 显示关联日志

#### FR-TASK-004: 任务编辑
- **描述**: 修改任务信息
- **前置条件**: 操作者为任务创建者、指派人、认领人、项目Admin或systemAdmin
- **输入**: 任务ID、需修改的字段
- **输出**: 操作成功提示
- **优先级**: P0
- **验收标准**:
  - [ ] 相关人员可编辑任务

#### FR-TASK-005: 任务状态切换
- **描述**: 更新任务状态
- **前置条件**: 操作者有任务编辑权限
- **输入**: 任务ID、新状态(NotStarted/InProgress/Completed/Cancelled)
- **输出**: 操作成功提示
- **业务规则**: 每次状态变更记录日志
- **优先级**: P0
- **验收标准**:
  - [ ] 可切换任务状态
  - [ ] 状态变更记录日志

#### FR-TASK-006: 任务进度更新
- **描述**: 更新任务完成进度
- **前置条件**: 操作者有任务编辑权限
- **输入**: 任务ID、进度值(0-100)
- **输出**: 操作成功提示
- **业务规则**: 
  - 进度值为0-100整数
  - 进度100%时状态自动变为Completed
- **优先级**: P1
- **验收标准**:
  - [ ] 可更新进度
  - [ ] 进度100%自动完成

#### FR-TASK-007: 任务认领
- **描述**: 用户认领未指派的任务
- **前置条件**: 任务无指派人且操作者为项目成员
- **输入**: 任务ID
- **输出**: 操作成功提示
- **业务规则**: 认领后操作者成为任务认领人
- **优先级**: P1
- **验收标准**:
  - [ ] 可认领未指派任务
  - [ ] 认领后成为认领人

#### FR-TASK-008: 任务指派
- **描述**: 将任务指派给用户
- **前置条件**: 操作者有任务编辑权限
- **输入**: 任务ID、被指派用户ID
- **输出**: 操作成功提示
- **业务规则**: 指派后该用户成为任务指派人
- **优先级**: P1
- **验收标准**:
  - [ ] 可指派任务
  - [ ] 指派后用户成为指派人

#### FR-TASK-009: 任务删除(软删除)
- **描述**: 逻辑删除任务
- **前置条件**: 操作者为项目Admin或systemAdmin
- **输入**: 任务ID
- **输出**: 操作成功提示
- **业务规则**: 任务不显示但数据保留
- **优先级**: P1
- **验收标准**:
  - [ ] 删除后任务不显示
  - [ ] 数据保留

#### FR-TASK-010: 任务恢复
- **描述**: 恢复已删除的任务
- **前置条件**: 操作者为项目Admin或systemAdmin
- **输入**: 任务ID
- **输出**: 操作成功提示
- **优先级**: P1
- **验收标准**:
  - [ ] 可恢复已删除任务

#### FR-TASK-011: AI任务拆分
- **描述**: 使用AI将任务拆分为子任务
- **前置条件**: 操作者为项目成员
- **输入**: 任务标题、任务描述、期望拆分数(可选)
- **输出**: AI返回的子任务列表
- **业务规则**: 
  - 调用外部AI服务
  - 支持一键批量创建子任务
- **优先级**: P3
- **验收标准**:
  - [ ] 可调用AI拆分任务
  - [ ] 支持批量创建子任务

### 3.4 分组管理模块

#### FR-GROUP-001: 分组创建
- **描述**: 在项目中创建任务分组
- **前置条件**: 操作者为项目成员
- **输入**: 项目ID、分组名称
- **输出**: 创建成功返回分组列表
- **优先级**: P1
- **验收标准**:
  - [ ] 可创建分组

#### FR-GROUP-002: 分组列表查看
- **描述**: 查看项目下所有分组
- **前置条件**: 操作者为项目成员
- **输入**: 项目ID
- **输出**: 分组列表，每个分组显示任务数量
- **优先级**: P1
- **验收标准**:
  - [ ] 显示分组列表
  - [ ] 显示每个分组任务数量

#### FR-GROUP-003: 分组编辑
- **描述**: 修改分组信息
- **前置条件**: 操作者为分组创建者、项目Admin或systemAdmin
- **输入**: 分组ID、新名称
- **输出**: 操作成功提示
- **优先级**: P2
- **验收标准**:
  - [ ] 可编辑分组名称
