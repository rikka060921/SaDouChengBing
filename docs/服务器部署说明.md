# ToDo 内部服务器部署说明

当前项目是 ASP.NET Core 8 Razor Pages，目标服务器为 Windows Server 2022。推荐使用 IIS + .NET 8 Hosting Bundle + MySQL 8。企业微信和腾讯会议已经接入真实网关，生产环境默认关闭，只有在凭据配置完整并通过验收后才可启用。

## 先确认网络入口

- `lab.icode8.net:13208` 是远程管理入口（通常是 RDP），只用于登录服务器，不是网站地址。
- 网站入口是 `https://test2.icode8.net`。DNS 必须把 `test2.icode8.net` 指向公网出口，公网防火墙/NAT 再转发到 `192.168.88.208`。
- 如果由上游网关负责 HTTPS，网关应将 HTTPS 请求转发到服务器 IIS 的 `80` 端口，并保留 `Host` 和 `X-Forwarded-Proto: https`。如果没有上游网关，则 IIS 需要直接绑定 443 和 `test2.icode8.net` 的证书。

你可以在服务器的 IIS 管理器中查看“站点 -> 绑定”：如果只有 `http / 80`，说明 HTTPS 在公网网关终止；如果存在 `https / 443` 且绑定了证书，说明 HTTPS 在 IIS 终止。根据目前“Web 发布端口 80”的信息，先按前一种情况配置。

不要把服务器管理员密码写入脚本或 Git。用户提供过的远程密码已经出现在对话中，部署完成后应立即更换，并建议创建单独的运维账号。

## 一、服务器准备

1. 安装 .NET 8 Hosting Bundle（不是只有 .NET SDK）。
2. 安装 MySQL 8，并创建数据库和一个专用应用账号。
3. 在 IIS 创建站点和应用程序池。应用程序池托管模型选择“无托管代码”。
4. 给 IIS 应用程序池身份授予发布目录下 `App_Data` 和 `wwwroot/uploads` 的读写权限。

## 二、一次性安装

在服务器上安装：

1. IIS（包括 IIS 管理控制台）。
2. .NET 8 Hosting Bundle。服务器如果要直接执行后续自动发布脚本，还需要 .NET 8 SDK 和 Git。
3. MySQL 8。网站和数据库在同一台服务器时，应用连接地址使用 `127.0.0.1:3306`，不需要开放 MySQL 公网端口。

创建目录并授权：

```powershell
New-Item -ItemType Directory -Force C:\Deploy\ToDo-source, C:\inetpub\ToDo\releases | Out-Null
New-WebAppPool -Name ToDo
Set-ItemProperty IIS:\AppPools\ToDo -Name managedRuntimeVersion -Value ''
New-Item -ItemType Directory -Force C:\inetpub\ToDo\current\App_Data, C:\inetpub\ToDo\current\wwwroot\uploads | Out-Null
New-Website -Name ToDo -Port 80 -PhysicalPath C:\inetpub\ToDo\current -ApplicationPool ToDo
icacls C:\inetpub\ToDo /grant 'IIS AppPool\ToDo:(OI)(CI)M' /T
```

如果 80 端口已经由反向代理或其他 IIS 站点占用，不要重复创建站点，改为在现有网关站点中配置反向代理，并保证请求最终到达该应用池。

## 三、首次发布

在开发机项目根目录执行：

```powershell
dotnet publish .\ToDo.Razor\ToDo.Razor.csproj -c Release -o .\publish
```

把 `publish` 目录复制到服务器，或在服务器上克隆当前分支后执行仓库中的 `deploy\Deploy-ToDo-Iis.ps1`。脚本会：拉取 `origin/Work-miracles(SaDouChengBing)`、生成带时间戳的 Release、保留附件和 Data Protection Keys、切换 IIS 站点路径并清理旧版本。发布目录中的 `web.config` 由 ASP.NET Core SDK 自动生成，不要删除。

服务器首次克隆：

```powershell
git clone --branch 'Work-miracles(SaDouChengBing)' https://team-git.icode8.net/DayDayUp/ToDo.git C:\Deploy\ToDo-source
Set-ExecutionPolicy -Scope Process Bypass
& C:\Deploy\ToDo-source\deploy\Deploy-ToDo-Iis.ps1
```

## 四、生产配置

不要把数据库密码、DeepSeek Key 或第三方 Secret 写入 Git。IIS 站点的环境变量使用双下划线映射配置层级：

```text
ASPNETCORE_ENVIRONMENT=Production
ConnectionStrings__DefaultConnection=server=127.0.0.1;port=3306;database=todo_prod;user=todo_app;password=服务器数据库密码;CharSet=utf8mb4;SslMode=None;AllowPublicKeyRetrieval=True
AI__ApiKey=DeepSeek Key
AI__ApiUrl=https://api.deepseek.com/chat/completions
AI__ModelName=deepseek-chat
Integrations__WeCom__Enabled=false
Integrations__TencentMeeting__Enabled=false
ForwardedHeaders__KnownProxies__0=反向代理网关的内网IP
```

需要启用真实外部集成时，再通过站点级环境变量补齐以下配置：

```text
Integrations__WeCom__CorpId=企业ID
Integrations__WeCom__AgentId=应用AgentId
Integrations__WeCom__Secret=应用Secret

Integrations__TencentMeeting__AppId=应用AppId
Integrations__TencentMeeting__SdkId=SDK ID
Integrations__TencentMeeting__SecretId=SecretId
Integrations__TencentMeeting__SecretKey=SecretKey
Integrations__TencentMeeting__DefaultUserId=调用方用户ID
Integrations__TencentMeeting__UseLocalCliFetch=false
```

配置完成并通过测试后，才把对应的 `Enabled` 改为 `true`。第三方 Secret 不得出现在 Git、日志或验收报告中。

开发机可以使用 User Secrets：

```powershell
dotnet user-secrets set "ConnectionStrings:DefaultConnection" "server=localhost;port=3306;database=todo123;user=root;password=实际密码;CharSet=utf8mb4;SslMode=None;AllowPublicKeyRetrieval=True" --project .\ToDo.Razor
dotnet user-secrets set "AI:ApiKey" "实际 DeepSeek Key" --project .\ToDo.Razor
```

`appsettings.Production.json` 只保留安全默认值和空配置项，真实连接串、Key 与 Secret 必须由服务器环境变量或服务器本机的安全配置注入。不要把这些值提交到 Git。

不要把 ToDo 的连接串和 API Key 设置成整个服务器的 Machine 环境变量，因为服务器上还有其他 IIS 网站。首次发布后，在当前 ToDo2 站点的发布目录执行：

```powershell
& C:\Deploy\ToDo-source\deploy\Set-ToDo-IisEnvironment.ps1 -SiteName ToDo2
```

脚本会交互式询问数据库密码、DeepSeek Key 和 HTTPS 网关 IP，并只写入 ToDo2 自己的 `web.config`。密码不会出现在命令行历史中，也不会提交到 Git。以后 `Deploy-ToDo-Iis.ps1` 会把这个 `web.config` 复制到新版本中。

只有上游网关负责 HTTPS、IIS 只接收 80 端口时，才在配置脚本中填写 HTTPS 网关 IP。该值必须是 IIS 实际看到的反向代理源 IP，不是网站域名或用户客户端 IP；如果 IIS 自己绑定 443，则直接回车留空。

本方案中 MySQL 与网站在同一台服务器，生产库使用从旧 `todo` 复制出来的 `todo_prod`，连接只走本机回环地址，可以使用 `SslMode=None;AllowPublicKeyRetrieval=True`，并且不要开放 3306 公网访问。若以后把数据库迁移到另一台服务器，再改为启用 TLS 和 `SslMode=Required`。

## 五、数据库初始化和升级

### 5.1 创建生产数据库账号

在服务器 MySQL 中创建应用账号。数据库名和账号可以按实际情况调整：

```sql
CREATE DATABASE IF NOT EXISTS todo_prod CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
CREATE USER IF NOT EXISTS 'todo_app'@'localhost' IDENTIFIED BY '请在服务器上设置的新密码';
GRANT ALL PRIVILEGES ON todo_prod.* TO 'todo_app'@'localhost';
FLUSH PRIVILEGES;
```

服务器环境变量中的连接串使用本机地址：

```text
server=127.0.0.1;port=3306;database=todo_prod;user=todo_app;password=服务器数据库密码;CharSet=utf8mb4;SslMode=None;AllowPublicKeyRetrieval=True
```

因为数据库和网站在同一台机器，`SslMode=None` 的流量不会离开服务器；不要把 3306 端口映射到公网。

### 5.2 迁移现有数据

在开发机导出当前数据库，命令会交互式提示数据库密码，不要把密码写在命令行：

```powershell
mysqldump -h 127.0.0.1 -P 3306 -u root -p --routines --triggers --single-transaction todo123 > .\todo123-backup.sql
```

把 `todo123-backup.sql` 通过安全方式复制到服务器，再在服务器导入：

```powershell
mysql -h 127.0.0.1 -P 3306 -u root -p todo123 < C:\Deploy\todo123-backup.sql
```

这一步会迁移用户、项目、任务、会议纪要、附件关联和系统配置数据。普通附件实体文件还需要单独复制 `wwwroot\uploads`，项目知识库原文件位于 `App_Data\ProjectDocuments`；如果开发机已有 `App_Data\DataProtection-Keys`，首次发布时也一起复制，避免登录 Cookie 失效。

如果服务器数据库是全新数据库，也可以不导入旧备份，直接让应用首次启动自动执行已提交的 EF Core 迁移，然后手动创建管理员账号。

首次部署前，在具备 .NET SDK 和数据库访问权限的机器上执行：

```powershell
dotnet ef database update --project .\ToDo.Context --startup-project .\ToDo.Razor --configuration Release
```

以后每次发布前先检查 `ToDo.Context/Migrations` 是否有新迁移，再执行同一命令。不要直接删除生产数据库或迁移历史。

## 六、后续同步发布

以后每次开发完成：

```powershell
git add .
git commit -m "描述本次改动"
git push origin 'Work-miracles(SaDouChengBing)'
```

然后在服务器执行：

```powershell
& C:\Deploy\ToDo-source\deploy\Deploy-ToDo-Iis.ps1
```

这会把服务器同步到远程分支最新提交。不要在服务器源代码目录直接改业务文件；服务器上的配置只放在机器环境变量，附件和 Data Protection Keys 由脚本保留。

如果希望 `git push` 后自动部署，需要在 Git 服务中配置 Windows Runner/Webhook，并让 Runner 执行这个脚本。首次部署建议先采用上面的手动触发方式，确认 IIS、DNS、数据库和备份均正常后再启用自动部署。

## 七、运行数据和备份

- `App_Data/DataProtection-Keys` 必须持久化，否则重启后登录 Cookie 可能失效。
- `wwwroot/uploads` 保存会议纪要和日报等普通附件；项目知识库原文件保存在 `App_Data/ProjectDocuments`，两者都必须纳入备份。
- MySQL 数据库、`App_Data`、`wwwroot/uploads` 建议每日备份，并至少保留最近 7 个备份。
- 生产环境使用 HTTPS；如果 IIS 前面还有反向代理，应把 HTTPS 证书配置在代理或 IIS 上。

## 八、验收清单

完整的 Agent、知识库、自动化、集成、安全和回滚验收项见 [正式验收清单](正式验收清单.md)。

1. 能登录并创建一个测试项目成员账号。
2. 在“会议纪要 -> 新建”选择项目后，能看到上一场会议、行动项状态和未完成任务。
3. 保存会议纪要后，在详情页点击“AI解析并同步任务”，确认任务列表出现新任务且重复点击不会重复通知。
4. 用非项目成员账号访问会议详情 URL，应返回无权限。
5. 上传一个会议附件并重新登录，确认附件仍可下载。
6. 重启 IIS 后确认仍能登录，说明 Data Protection Key 目录权限和持久化正确。
