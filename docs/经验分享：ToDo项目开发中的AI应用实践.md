# ToDo项目开发中的AI应用实践

## 1. 概述

### 1.1 文档目的

本文档总结在ToDo项目开发过程中，如何使用AI技术辅助完成各阶段开发工作的推荐做法。核心主题是"如何使用AI辅助开发"，而非"ToDo系统有哪些AI功能"。

### 1.2 开发流程概览

```
输入主题 → AI确认需求 → 需求文档 → 需求规格 → 概要设计 → 详细设计 
→ 测试计划 → 辅助开发 → 编写单元测试 → 执行单元测试 → 审查报告
```

在上述流程中，AI并非替代人工，而是作为"协作伙伴"参与各阶段工作，提升效率的同时保证质量。

### 1.3 核心原则

| 原则 | 说明 |
|-----|------|
| 人工主导 | AI辅助细化，人工校验和纠正 |
| 效率优先 | AI处理重复性工作，人工聚焦创造性工作 |
| 全程可追溯 | AI输出需人工审核，保留决策记录 |

## 2. 需求阶段AI应用

### 2.1 需求确认

**输入**：业务负责人提出的原始需求（如：需要一个任务管理系统）

**AI辅助工作**：
- 分析需求背景和目标
- 提取关键实体和关系
- 识别潜在风险和约束
- 生成初步用户故事列表

**输出示例**：
```
原始需求：需要一个任务管理系统

AI分析结果：
- 核心实体：用户、项目、任务、分组
- 核心关系：用户创建/参与项目，项目包含任务，任务可分组
- 初步用户故事：
  1. 用户可以创建和登录账号
  2. 用户可以创建项目并管理成员
  3. 项目成员可以创建和认领任务
  4. ...
- 潜在风险：权限控制复杂度、多人协作冲突
```

### 2.2 需求文档撰写

**人工工作**：提供文档框架和核心要点

**AI辅助工作**：
- 扩展和细化每个需求点
- 生成标准化的需求描述格式
- 检查文档完整性和一致性
- 补充遗漏的边界情况和异常场景

**Prompt模板**：

引用全文：
```
请参考`需求：需求分析说明书`文档，帮我完成`需求：需求规格说明书`中XX模块的需求细化
```

引用片段：
```
请参考`需求：需求分析说明书` 第50-100行（用户与权限相关章节），帮我完成`需求：需求规格说明书`中用户管理模块的需求细化
```

### 2.3 需求规格定义

**人工工作**：确定功能范围和优先级

**AI辅助工作**：
- 将需求拆解为可测试的功能点
- 生成验收标准建议
- 识别功能间的依赖关系
- 补充非功能需求描述

## 6. Prompt工程要点

### 6.1 设计原则

| 原则 | 说明 | 示例 |
|-----|------|-----|
| 明确角色 | 指定AI扮演的角色 | "你是一个资深.NET开发工程师" |
| 结构化输入 | 清晰分隔输入内容 | 使用【】或###分隔 sections |
| 具体约束 | 明确输出格式和限制 | "只返回JSON，不要其他文字" |
| 示例引导 | 提供输出示例 | 给出期望的格式示例 |

### 6.2 常见模式

**模式一：角色+任务+约束**
```
你是一个[角色]，请帮我完成[任务]，要求如下：
1. [约束1]
2. [约束2]
3. [约束3]
```

**模式二：输入+示例+输出要求**
```
输入：{input}
示例格式：
{example}
请按上述格式输出，要求：{requirements}
```

**模式三：渐进式提问**
```
第一步：分析以下需求，识别核心实体
{requirement}
第二步：基于分析结果，设计数据模型
第三步：生成接口定义
```

### 6.3 输出控制

| 目标 | 方法 |
|-----|------|
| 限制输出长度 | "总结为3点以内"、"不超过200字" |
| 保证格式稳定 | temperature=0.3, 明确JSON结构 |
| 避免无关内容 | "只返回代码，不要解释" |
| 便于解析 | 指定输出格式，如JSON、表格、分点列表 |

## 7. 质量保障

### 7.1 AI输出审核清单

| 阶段 | 审核要点 |
|-----|---------|
| 需求 | 是否符合业务实际？边界条件是否完整？ |
| 设计 | 是否可行？是否与其他模块冲突？ |
| 代码 | 是否符合编码规范？是否有潜在bug？ |
| 测试 | 用例是否覆盖核心路径？断言是否正确？ |

### 7.2 人机协作流程

```
人工输入 → AI处理 → AI输出 → 人工审核 → 通过/打回重做
                              ↓
                        通过 → 进入下一阶段
                        打回 → 补充信息后重新提交
```

### 7.3 常见问题处理

| 问题 | 原因 | 处理方式 |
|-----|------|---------|
| AI理解偏差 | 输入不够明确 | 补充背景信息，分步骤提问 |
| 输出格式不符 | 约束不够具体 | 明确输出格式，提供示例 |
| 内容不准确 | AI产生幻觉 | 人工校验，重要结论需核实 |
| 边界情况遗漏 | 未明确要求 | 明确要求检查边界情况 |

## 8. 效率提升总结

### 8.1 各阶段AI辅助效果

| 阶段 | 人工耗时 | AI辅助后 | 效率提升 |
|-----|---------|---------|---------|
| 需求分析 | 2-3天 | 0.5-1天 | 70%+ |
| 文档撰写 | 1-2天 | 0.5天 | 60%+ |
| 概要设计 | 1-2天 | 0.5天 | 60%+ |
| 详细设计 | 2-3天 | 1天 | 50%+ |
| 代码开发 | - | - | 30-40% |
| 单元测试 | - | - | 40-50% |

### 8.2 关键成功因素

1. **人工主导**：AI是辅助工具，最终决策权在人工
2. **明确输入**：高质量输入才能带来高质量输出
3. **迭代优化**：通过多轮对话持续改进输出
4. **严格审核**：对AI输出必须进行人工校验
