# Agent 执行计划与联网搜索

## 本轮变化

日常路径：创建任务 → 自动匹配 Agent → 生成执行计划 → 人工确认 → 按计划执行 → 敏感操作单独审批 → 人工验收。

- 计划显示在任务详情，并汇入“待我处理”。不新增独立规划管理页面。
- 计划描述目标、步骤、工具、审批和交付要求；不是自动创建一批子任务。
- 新入队的自动任务、追加评论和返工执行均先确认计划。历史已入队工作项保留原流程，避免升级打断执行。
- 规划阶段关闭业务工具和搜索工具；不会写入任务评论、交付凭证或把业务任务改为进行中。
- 可以填写意见并重新生成。确认绑定计划版本、任务内容、分配版本与 Agent 运行版本；输入变化会拒绝旧确认或重新规划。
- 创建人、验收人需仍为项目成员；项目负责人、项目管理员、系统管理员也可确认。停用或删除的用户不得确认。
- 双击确认不会重复入队。后台重启不会自动批准等待中的计划。
- 计划审批不替代工具授权、敏感操作审批，也不等于任务完成。

## 联网搜索配置

实现 Tavily 基础搜索，固定访问 https://api.tavily.com/search，不开放任意 URL 抓取。接口参考：[Tavily 官方文档](https://docs.tavily.com/documentation/api-reference/endpoint/search)。

搜索默认关闭，未配置不影响其他 Agent 功能。配置模板：deploy/agent-web-search.example.json。该模板不会自动加载，部署时将对应设置合并到服务器配置，或设置进程环境变量：

| 环境变量 | 值 |
| --- | --- |
| AgentWebSearch__Enabled | true |
| AgentWebSearch__ApiKey | 自己注册获得的 Tavily API Key |
| AgentWebSearch__MaxResults | 5 |
| AgentWebSearch__TimeoutSeconds | 15 |

密钥只保存在部署环境，不写入源码、提交说明或共享日志。IIS 下需让应用进程读取这些变量，并回收对应应用池。

再在“Agent 管理”编辑选定 Agent：
1. 能力标签增加 web.search。
2. 工具权限启用“联网搜索公开资料”。
3. 保存并启用。
4. 创建任务时明确写“联网搜索公开资料”；只写“整理资料”不会自动外发查询。

一次执行会话最多调用 3 次搜索，每次最多 5 条结果。基础搜索关闭自动参数、生成答案与全文抓取，限制响应大小与超时，不自动跟随重定向。现有 Agent 不会被批量授予搜索权限。

搜索词会发送给供应商，仅用于公开主题。后端补充拦截常见密钥格式和个人邮箱，但不承诺识别一切敏感内容；私人资料整理 Agent 不应开启此工具。项目访问权和当前搜索权限会在调用时复核。

结果保留标题、链接、摘要、查询词和检索时间，写入工具审计。最终交付追加实际检索来源；没有调用、调用失败或没有来源时标记“联网核验未完成”，不会仅凭模型声明标记搜索成功。真实网页内容仍须核对，来源记录不代表自动验证所有结论。

价格与免费额度以 [Tavily 官方定价](https://docs.tavily.com/documentation/api-credits) 为准。系统不代为开通付费或充值。

## 推荐验收

### 不依赖搜索 API 的主流程

1. 新建数字员工任务，例如“汇总当前项目任务进展，只读、不写回”。
2. 在“待我处理”打开执行计划。确认前，业务任务应仍未开始，不应有交付凭证。
3. 填写“先说明信息缺口”，点击“按意见重新生成”，检查版本递增。
4. 确认新版计划，观察执行状态变化；完成后进入人工验收，而不是直接完成。
5. 未授权成员不应看见确认按钮；直接伪造请求也应被后端拒绝。
6. 打开旧页面后修改任务描述，再用旧页面确认，应提示计划过期。
7. 要求修改项目等敏感操作的任务，计划确认后仍须独立审批。

### 搜索流程

1. 配置密钥并授予搜索能力、工具权限。
2. 创建“联网搜索公开的 ASP.NET Core 官方文档，列出来源，不写回”任务。
3. 确认计划，检查 Session 的 web.search 调用及最终来源链接。
4. 关闭搜索配置后重做，检查明确失败提示和“联网核验未完成”，不能视为搜索已验证。
5. 使用不含联网要求的任务，确认不调用搜索。
