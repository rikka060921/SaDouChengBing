# Agent 执行链路简化 · 2026-09-23

## 范围与基线

以个人 GitHub 仓库 `main` 的 `0400973` 为基线，在其独立本地检出目录修改。没有覆盖原团队仓库的未提交工作，也没有导入旧团队仓库历史。本轮按所有者最新要求提交并推送 GitHub；没有部署、连接正式业务数据库或调用真实模型、搜索服务。

原快照首次 `--no-restore` 测试因缺少资产文件失败；还原依赖后，测试项目仍有两处原有编译错误：`AgentSimplifiedAutomationTests` 调用已不存在的 EditModel 五参数构造函数及双参数 OnGet。此前文档中的 416 项通过不是这个快照的有效基线。本轮先对齐接口，再验证新旧流程。

不新增表、字段、迁移；不删除会议、任务、资料、审批、队列、版本、交付证据或任务内私有 AI 协助。

## 用户现在如何使用

创建 Agent 仍只填名称、主要用途、工作要求。列表展示实际注册能力、启用状态、允许的操作及审批方式，不再以模型名称作为主要信息。

所有 Agent（轻量和旧自定义）从“工作要求”进入统一简化编辑页，只修改名称、用途说明、工作要求。已有模型、工具、资料授权、停用状态和交付规则不被重置。修改名称不等于增加能力。需要不同用途可创建对应助手；维护人员可进入独立 Technical 页面检查模型、工具和交付规则，旧测试、版本及发布兼容机制保留。

旧 Create/id 编辑书签和提交重定向到统一编辑入口。编辑采用版本检查：他人已修改、存在未生效配置或正在灰度时不会覆盖；冲突时保留输入。管理与技术入口仍仅系统管理员可访问，不扩大成员权限。

## 一套决策规则，四处复用

`AgentTaskIntentMatcher.Analyze/ForTask` 返回内容用途、明确请求的工具、是否要求先确认计划。它是规则解释器，不是自由语义理解模型；不使用 AI 自评分。

1. 调度使用同一用途和工具集合，检查实际运行版本、职责、资料读取/写入范围及工具授权。多候选仍按待处理量、ID 排序，无综合评分。
2. 入队按该决定设置 RequiresPlan。分析、纪要整理、文档草稿、拆分建议和普通公开检索直接执行。写入任务先规划；仅明确要求确认或已有人工调整意见时等待人。历史 RequiresPlan 标志不批量改写。
3. 每轮工具暴露和实际工具调用前，按正式工作项重新检查对应工具集合；拥有工具不等于当前任务可以使用所有工具。原生工具和旧 agent-actions 协议都受限制。调整计划意见只能收窄原任务工具范围，不能另行授予工具。
4. 自动验收读取同一决定，但继续独立执行更严格的硬检查和无工具复核。分类正确不等于验收通过。

排队期间任务从只读改成写入或“先确认计划”时，执行前刷新系统生成的任务提示并补上规划；已开始会话仍沿用既有版本、取消/变更检查和交付防过期逻辑。

| 用户要求 | 直接执行/规划 | 系统行为 |
|---|---|---|
| 根据需求分析写一份概要设计文档 | 直接 | 读取授权资料，交付草稿，不要求资料写工具 |
| 先给我看概要设计草稿，不保存到项目资料 | 直接 | 只输出内容，没有保存审批 |
| 把概要设计保存到项目资料库 | 规划 | 需要资料写工具和分类写权限；高风险人工审批，不自动验收此写入 |
| 修改资料库里已有设计并保存 | 规划 | 同上，保留原有工具与审批约束，不承诺任意文件编辑能力 |
| 拆分需求，给出 5 个任务建议，不要创建任务 | 直接 | 输出建议，不开放 task.create |
| 在系统里创建这 5 个子任务 | 规划 | 开放 task.create，按现有中风险独立审核；不因规则简化自动验收新建任务 |
| 分析当前项目风险和下一步工作 | 直接 | 交付有依据的分析，满足检查后可自动完成 |
| 联网查 ASP.NET Core 8 最佳实践并给建议 | 直接 | 仅开放已授权 web.search，必须有真实来源；不得发送内部原文、个人信息或密钥 |
| 生成周报 | 直接 | 只生成内容；明确“保存到系统”才开放 report.create |
| 先确认计划 / 先给我执行方案 / 先不要执行 | 等待计划确认 | 不先产出正式交付，不先执行业务工具 |

“先给我看草稿”是成果要求，不是计划确认。否定保存、创建、修改或只要建议的表达优先限制写入。无法识别的说法不会凭猜测开放写工具，需把动作和对象写清楚。

## 权限和验收没有被简化掉

- 用户/项目/资料分类权限、工具白名单、每次执行时的权限检查、高风险人工审批与中风险独立审核继续存在。
- 持久化队列、并发抢占、幂等、有限重试、正常停机恢复、未知副作用不盲目重放继续存在。
- 正式任务与私有 AI 协助仍使用不同队列和策略；私有协助不写任务、评论或正式交付，不因这次改动获得工具。
- 只读成果可以自动验收；须有上下文读取记录、明确要求、完整来源，无失败/拒绝/未决工具、未完成子任务或其他待处理要求，再经独立无工具复核。
- 保存报告仍必须有本次执行真实生成、归属正确的完整报告记录，复核期间再次核对来源、产物、任务和权限。其他写入不被扩大到报告自动验收范围。
- 复核失败或服务不可用，保留交付并转人工，不重复执行业务写入。模型自称完成、搜索链接或文字长度本身不构成验收证明。
- NoCandidate 现在区分用途不明、职责不齐、已停用/不接单、资料不可读、缺工具和缺分类写权限，并给出具体处理方向，不泄露配置或密钥。
