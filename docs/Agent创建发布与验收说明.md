# Agent 创建、测试、发布与验收说明

## 1. 管理员如何创建 Agent

进入“Agent 管理”后选择“新建 Agent”，先选一种模板：

- 只读分析 Agent：只读取授权上下文，适合分析、总结和风险检查；默认不开业务写入工具。
- 任务协作 Agent：围绕指定任务工作，可按权限申请评论、创建或修改任务。
- 事件自动化 Agent：响应项目事件，适合逾期、返工、会议发布后的自动检查。

模板只是安全起点。管理员仍需确认 Agent 名称、唯一 Key、职责、系统提示词、能力标签、数据范围、工具权限和验收合同。

能力标签与工具权限不是一回事：能力标签用于调度器判断“适不适合做”，工具权限决定 Agent “能不能写入系统”。保存后 Agent 一定处于草稿状态。

## 2. 验收合同怎么填写

每个 Agent 必须明确：

1. 目标：最终解决什么问题。
2. 输入要求：必须选择项目、任务或提供哪些事实。
3. 必须输出：回答至少包含哪些结构。
4. 成功标准：什么结果才算合格。
5. 禁止行为：不能越过的权限和业务边界。
6. 隔离测试任务：用于验证当前配置的代表性任务。
7. 必须出现的关键词：每行一个，测试输出必须全部命中。
8. 禁止出现的内容：每行一个，命中任何一项即失败。

验收关键词应选择稳定的章节名，例如“结论”“证据”“下一步”，不要选择具体项目数据或模型可能使用同义词替代的长句。

## 3. 隔离测试做了什么

隔离测试与正式运行使用同一个模型配置和同一套项目访问权限，但有三项重要差异：

- 不向模型提供任何业务工具；
- 不解析或执行模型输出的动作协议；
- 只记录授权上下文读取审计、AI Session 和测试结果。

测试通过需要同时满足：输出非空、出现全部必需关键词、不出现禁用内容、模型没有请求原生工具、结果没有旧式工具调用协议。

测试失败时页面会显示具体原因。修改配置或验收合同后版本递增，并必须重新测试。

## 4. 发布后的状态

| 状态 | 是否能运行 | 说明 |
| --- | --- | --- |
| 草稿 | 否 | 新建或配置刚被修改 |
| 测试中 | 否 | 已运行隔离测试；通过时具备发布条件 |
| 已发布 | 是 | 可以手工运行、自动调度或按事件执行 |
| 已暂停 | 否 | 暂停接收新任务；配置没变时可重新发布 |
| 已归档 | 否 | 已退出使用，不能重新发布 |

存在未完成工作项的 Agent 不允许归档，避免执行记录失去归属。

## 5. 验收操作

1. 新建一个只读分析 Agent，确认保存后状态为“草稿”。
2. 不运行测试直接点击发布，确认系统拒绝。
3. 选择一个有权限的测试项目运行隔离测试，确认页面产生测试记录和 Session。
4. 确认测试期间没有任务评论、任务变更、报告创建等业务写入。
5. 故意增加一个模型不会输出的必需关键词，确认测试失败且无法发布。
6. 恢复合理关键词并测试通过，发布 Agent，确认 Agent 中心可以运行它。
7. 编辑已发布 Agent，确认它回到草稿、版本递增且旧测试结果失效。
8. 再次测试和发布，暂停后确认不再进入调度候选。

自动化回归位于 `ToDo.Test/AgentProductLifecycleTests.cs`。
