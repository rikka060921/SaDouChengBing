# 任务拆分与会议归档修复说明

基于提交 `1715443` 修复。本次没有连接或修改线上数据库。

## 修复内容

1. **首次 AI 任务拆分返回 500**：为任务字典指定明确的表单绑定前缀，避免框架将 `ProjectId` 等普通字段名转换成整数键。实际 HTTP 回归覆盖项目列表入口、首次提交和结果页面渲染。
2. **删除任务后，保存校验失败导致行错位**：保留原有列表索引和删除标记，隐藏已删除行，不在重新渲染时压缩索引。未删除任务及其编辑内容继续保留。
3. **重复提交生成重复任务**：每次拆分生成独立批次标识；保存时将批次记录与任务在同一次数据库事务内提交，利用用户与批次组成的唯一主键防止重复和并发创建。失败事务不占用批次，允许纠正后重试；前端同时禁用保存中的按钮，返回页面时恢复按钮。
4. **截断 JSON 导致拆分失败**：复用现有安全修复逻辑，仅保留完整的任务对象，并明确提示用户检查遗漏。不会补造被截断的半条任务。
5. **通过议题归档绕过任务审核**：归档前校验任务所属项目及审核权限，统一遵循系统管理员、项目负责人、项目管理员、指定审核人的权限规则；非特权创建者不能自行验收。页面仅向有审核权限的人显示验收归档入口，确认文字说明关联任务会完成。
6. **AI 判断失败却自动通过验收**：移除“提及任务标题即通过”的关键词降级路径。AI 异常、无结果、字段缺失或明确拒绝时，任务保持待审核、议题保持活跃；完整且符合规则的结果继续走原有会议验收流程。
7. **归档后 Agent 回执仍待验收**：议题归档同步更新任务和 Agent 状态、交付回执、审核人及时间、表现反馈、任务审核评论、操作日志和通知，并取消尚未完成的相关工作项。这些变更由调用方统一提交。
8. **腾讯会议刷新始终读旧缓存**：会议列表和转写内容在线优先，查询失败或离线时使用已有缓存。空转写及无效响应不覆盖已有有效内容；缓存采用临时文件原子替换，认证检查复用有超时的 CLI 调用。

## 验证

- 162 项测试通过，其中新增 21 项回归用例。
- 页面 HTTP 测试使用隔离内存数据库和模拟 AI；数据库并发、事务回滚及 Agent 验收测试使用 SQLite；会议缓存测试使用模拟 CLI。
- MySQL 迁移 SQL 生成测试确认升级只创建 `TaskSplitSubmissions`，不删除或修改现有业务表。
- 真实 AI 供应商和腾讯会议账号的在线可用性不在这些离线测试的覆盖范围内。

## 部署与验收

本次包含迁移 `20260912135247_AddTaskSplitSubmissions`。完整发布新版应用，现有启动迁移流程会创建批次表；仅替换页面文件不足以完成升级。

建议验收顺序：

1. 项目列表 → AI 任务拆分 → 输入内容，确认正常出现可编辑任务。
2. 删除一条任务，修改剩余内容并保存，确认保存条数及内容正确。
3. 对同一批次重复提交，确认只创建一次。
4. 普通非审核成员不能把待审核任务通过议题归档改成完成；指定审核人或项目管理员可验收归档。
5. 验收后检查任务状态、Agent 交付回执、审核记录和操作日志一致。
6. 腾讯会议新增录制或修订转写后刷新，确认获取最新结果。

修复只约束后续操作，不会自动修改历史上已经误归档、重复创建或漏记验收的数据。
