# ToDo 服务器接管与发布指南

## 1. 文档用途

本文面向第一次接管本项目的开发人员和服务器管理员，说明以下内容：

- 当前服务器、IIS、MySQL、代码仓库和发布目录的实际状态。
- 开发人员如何通过 Visual Studio 提交和推送代码。
- 服务器管理员如何手动拉取、发布、验收和回滚。
- 如何备份数据库、附件和登录密钥。
- 常见故障如何定位和处理。

本文不得填写服务器密码、MySQL 密码、DeepSeek API Key、Git Token 或其他第三方 Secret。文中的密码均为占位符，真实值由接管人员通过公司的安全渠道获取。

```powershell

    Select-Object Name,InstallState

dotnet --list-sdks

Get-Service -Name "MySQL*" |
    Format-Table Status,Name,DisplayName
```

- 存在 `Microsoft.AspNetCore.App 8.x` 和 `Microsoft.NETCore.App 8.x`。
- Git 能显示版本号。
- `MySQL80` 为 `Running`。

### 4.2 检查 IIS 网站

```powershell
Import-Module WebAdministration

Get-Website |
    Select-Object Name,State,PhysicalPath,ApplicationPool

Get-WebBinding |
    Format-Table protocol,bindingInformation,ItemXPath -AutoSize

Get-WebAppPoolState -Name "ToDo2"
```

必须确认：

- `ToDo2` 为 `Started`。
- 绑定是 `*:80:test1.icode8.net`。
- 应用程序池是 `ToDo2`。
- 物理路径位于 `C:\inetpub\ToDo2\releases` 下。

### 4.3 检查服务器源码

```powershell
git -C "C:\Deploy\ToDo-source" status
git -C "C:\Deploy\ToDo-source" branch --show-current
git -C "C:\Deploy\ToDo-source" log -1 --oneline
```

预期结果：

- 工作区为 `working tree clean`。
- 当前分支为 `Work-miracles(SaDouChengBing)`。
- 最新提交与远程仓库一致。

服务器源码目录只用于拉取和发布，不得直接修改业务代码。发现本地修改时先停止发布并查明来源，不要直接执行 `git reset --hard`。

## 5. 开发人员如何提交和推送

正式流程使用 Visual Studio 内置 Git 工具。

1. 在开发机打开解决方案 `ToDo.sln`。

推送完成后，开发人员应把以下信息交给服务器管理员：

## 6. 服务器手动拉取和发布

当前正式流程是“开发人员推送，服务器管理员手动拉取并发布”。服务器没有配置自动部署。

### 6.1 发布前检查和备份

查看服务器源码是否干净：

```powershell
git -C "C:\Deploy\ToDo-source" status --short
```

正常时没有任何输出。如果有输出，停止发布并确认文件来源。

记录当前版本：

```powershell
Import-Module WebAdministration

$currentSite = Get-Website -Name "ToDo2"
$currentSite |
    Format-List Name,State,PhysicalPath,ApplicationPool

git -C "C:\Deploy\ToDo-source" log -1 --oneline
```

重要发布前备份数据库，参见第 9 节。

### 6.2 只拉取代码

```powershell
git -C "C:\Deploy\ToDo-source" pull --ff-only origin "Work-miracles(SaDouChengBing)"
```

参数说明：

- `-C`：让 Git 在指定目录中执行。
- `pull`：从远程获取并合并最新提交。
- `--ff-only`：只允许快进更新，避免服务器自动生成合并提交。
- `origin`：远程仓库名称。
- 最后的字符串：正式发布分支。

拉取后确认提交号：

```powershell
git -C "C:\Deploy\ToDo-source" log -1 --oneline
```

### 6.3 执行发布

```powershell
Set-ExecutionPolicy -Scope Process Bypass

& "C:\Deploy\ToDo-source\deploy\Deploy-ToDo-Iis.ps1" `
    -SiteName "ToDo2" `
    -AppPoolName "ToDo2" `
    -SiteRoot "C:\inetpub\ToDo2"
```

参数说明：

- `Set-ExecutionPolicy -Scope Process Bypass`：只在当前 PowerShell 窗口允许执行本地部署脚本，关闭窗口后失效。
- `-SiteName`：要切换的 IIS 网站。
- `-AppPoolName`：网站使用的应用程序池。
- `-SiteRoot`：保存版本目录的站点根目录。
- `-HealthCheckUrl`：切换后用于确认数据库已就绪的地址，默认 `http://127.0.0.1/health/ready`。
- `-HealthCheckHost`：IIS 使用主机名绑定时发送的 Host；留空会从站点 HTTP 绑定自动识别。

部署脚本会自动：

1. 检查服务器源码目录是否干净。
2. 获取并拉取正式分支最新提交。
3. 执行 `dotnet publish -c Release`。
4. 创建 `C:\inetpub\ToDo2\releases\时间戳`。
5. 复制上一版本的生产 `web.config`、上传文件和 Data Protection Keys。
6. 设置运行时写入目录权限。
7. 等待应用程序池停止，切换 IIS 物理路径，再启动应用程序池。
8. 重试检查 `/health/ready`；启动或数据库迁移失败时自动切回上一文件版本。
9. 健康检查通过后保留最近 3 个发布版本。

成功时最后会显示：

```text
Deployed Work-miracles(SaDouChengBing) to C:\inetpub\ToDo2\releases\时间戳
```

不要在脚本运行过程中关闭 PowerShell 窗口。

## 7. 首次生产配置或密钥变更

只有首次部署、数据库密码变更、DeepSeek Key 变更或网关 IP 变更时才执行：

```powershell
& "C:\Deploy\ToDo-source\deploy\Set-ToDo-IisEnvironment.ps1" `
    -SiteName "ToDo2"
```

脚本会依次询问：

1. `todo_app` 的 MySQL 密码，不是 MySQL `root` 密码。
2. DeepSeek API Key。
3. HTTPS 网关的内网源 IP。

当前脚本通过交互提示读取这些值，输入内容可能在远程桌面窗口中可见。操作时不要共享屏幕，不要复制包含输入值的控制台内容，也不要把真实值写进命令行参数。

当前日志观察到的网关来源为 `192.168.88.254`，但必须先由网络管理员确认。不要填写域名、服务器 IP `192.168.88.208` 或用户电脑 IP。

实际值会写入当前 ToDo2 发布目录的 `web.config`。该文件不会提交到 Git，但具有服务器管理员权限的人可以读取，因此应严格控制服务器登录权限。

部署脚本会把当前生产 `web.config` 复制到新版本。正常日常发布不需要重复输入数据库密码和 DeepSeek Key。

```powershell
Get-Website -Name "ToDo2" |
    Format-List Name,State,PhysicalPath,ApplicationPool
```

应用程序池和网站都应为 `Started`，物理路径应为刚生成的新时间戳目录。

访问：

```text
https://test1.icode8.net
```

至少完成以下检查：

1. 使用已有账号登录。
2. 查看旧项目、任务、会议纪要和日报是否存在。
3. 创建一个测试团队成员账号；涉及权限改动时还要测试创建系统管理员。
4. 创建或编辑测试任务。
5. 打开会议纪要并检查上次会议、行动项和未完成任务。
6. 上传一个测试附件并确认可以下载。

## 9. 数据库备份和恢复

### 9.1 创建数据库备份

```powershell
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
$backupPath = "C:\Deploy\Backups\ToDo2-$stamp"
$mysqldump = "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysqldump.exe"

New-Item -ItemType Directory -Force -Path $backupPath | Out-Null

& $mysqldump `
    --host=127.0.0.1 `
    --port=3306 `
    --user=root `
    --password `
    --routines `
    --triggers `
    --single-transaction `
    --result-file="$backupPath\todo_prod.sql" `
    todo_prod

Get-Item "$backupPath\todo_prod.sql" |
    Select-Object FullName,Length,LastWriteTime
```

`--password` 会交互式询问密码，避免密码进入 PowerShell 历史。备份文件大小不能为 0。

### 9.2 备份附件和登录密钥

```powershell
Import-Module WebAdministration

$sitePath = [string](Get-Website -Name "ToDo2").PhysicalPath

Copy-Item -Path (Join-Path $sitePath "wwwroot\uploads") `
    -Destination $backupPath `
    -Recurse `
    -Force

Copy-Item -Path (Join-Path $sitePath "App_Data") `
    -Destination $backupPath `
    -Recurse `
    -Force
```

`wwwroot\uploads` 是会议纪要和日报等普通附件实体文件，`App_Data\ProjectDocuments` 是受权限保护的项目知识库原文件，数据库只保存关联信息。`App_Data\DataProtection-Keys` 用于保护登录 Cookie；整个 `App_Data` 和 `wwwroot\uploads` 都必须备份。

### 9.3 恢复数据库

数据库恢复会覆盖或改变生产数据，必须先停止网站、再次备份当前数据库，并获得负责人确认。

```powershell
Import-Module WebAdministration
Stop-WebAppPool -Name "ToDo2"

$mysql = "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe"

& $mysql `
    --host=127.0.0.1 `
    --port=3306 `
    --user=root `
    --password `
    --database=todo_prod `
    --execute="source C:/Deploy/Backups/指定备份目录/todo_prod.sql"
```

恢复完成并核对无误后再启动：

```powershell
Start-WebAppPool -Name "ToDo2"
```

不要在没有备份和负责人确认的情况下执行恢复、删除数据库或删除迁移历史。

### 9.4 EF Core 数据库迁移

当前应用启动时会检查并应用仓库中已经提交的 EF Core 迁移。开发人员修改实体或数据库结构时，必须在开发机生成迁移并随代码一起提交：

```powershell
dotnet ef migrations add "清晰的迁移名称" `
    --project .\ToDo.Context `
    --startup-project .\ToDo.Razor
```

发布包含迁移的版本前：

1. 开发人员说明迁移内容和是否可逆。
2. 服务器管理员完整备份 `todo_prod`。
3. 确认迁移不会删除仍需保留的生产字段或数据。
4. 发布后检查应用日志和迁移历史。

查看迁移历史：

```powershell
$mysql = "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe"

& $mysql `
    --host=127.0.0.1 `
    --port=3306 `
    --user=todo_app `
    --password `
    --database=todo_prod `
    --execute="SELECT MigrationId,ProductVersion FROM __EFMigrationsHistory ORDER BY MigrationId;"
```

不要手工删除 `__EFMigrationsHistory`，也不要为了绕过迁移错误直接修改迁移记录。

## 10. 版本回滚

### 10.1 查看可回滚版本

```powershell
Get-ChildItem "C:\inetpub\ToDo2\releases" -Directory |
    Sort-Object Name -Descending |
    Select-Object Name,FullName,LastWriteTime
```

### 10.2 将 IIS 切回上一版本

先把下面的路径替换成确认可用的旧版本目录：

```powershell
Import-Module WebAdministration

$previousRelease = "C:\inetpub\ToDo2\releases\旧版本时间戳"

if (-not (Test-Path (Join-Path $previousRelease "ToDo.Razor.dll"))) {
    throw "所选目录不是有效的 ToDo 发布版本。"
}

Stop-WebAppPool -Name "ToDo2"

do {
    Start-Sleep -Seconds 1
    $state = (Get-WebAppPoolState -Name "ToDo2").Value
} while ($state -ne "Stopped")

Set-ItemProperty "IIS:\Sites\ToDo2" `
    -Name physicalPath `
    -Value $previousRelease

Start-WebAppPool -Name "ToDo2"
```

回滚后重新执行第 8 节验收。应用版本回滚不会自动回滚数据库；如果新版本包含不可逆数据库变更，必须依据发布前数据库备份单独制定恢复方案。

## 11. 常见故障处理

### 11.1 `HTTP Error 500.30`

含义：ASP.NET Core 应用启动失败。

优先检查：

- `App_Data\DataProtection-Keys` 是否有写权限。
- `web.config` 是否存在生产连接字符串。
- MySQL 服务是否运行。
- .NET 8 Hosting Bundle 是否安装。

查看最近事件：

```powershell
Get-WinEvent -LogName Application -MaxEvents 80 |
    Where-Object {
        $_.ProviderName -match "IIS|ASP.NET|\.NET Runtime"
    } |
    Select-Object -First 15 TimeCreated,ProviderName,Id,Message |
    Format-List
```

### 11.2 `Access to App_Data\DataProtection-Keys is denied`

```powershell
Import-Module WebAdministration

$sitePath = [string](Get-Website -Name "ToDo2").PhysicalPath
$dataPath = Join-Path $sitePath "App_Data"

New-Item -ItemType Directory -Force -Path $dataPath | Out-Null

& icacls.exe $dataPath `
    /grant "IIS AppPool\ToDo2:(OI)(CI)M" `
    /T `
    /C
```

当前部署脚本已自动执行该授权。再次出现时应检查是否绕过脚本手工复制了发布目录。

### 11.3 应用程序池停在 `Stopping`

不要立即反复执行启动命令。先检查：

```powershell
Get-WebAppPoolState -Name "ToDo2"
```

等待状态变为 `Stopped` 后再执行：

```powershell
Start-WebAppPool -Name "ToDo2"
```

当前部署脚本已经加入最长 60 秒的状态等待。

### 11.4 `web.config does not contain an aspNetCore element`

当前配置脚本已兼容以下两种结构：

```text
/configuration/location/system.webServer/aspNetCore
/configuration/system.webServer/aspNetCore
```

如果仍出现该错误，应确认 IIS 网站指向的是 `dotnet publish` 生成的完整目录，而不是源码目录。

### 11.5 创建用户提示通用错误页

生产环境通用错误页不会向浏览器显示详细异常。页面中的 `Development Mode` 是模板固定说明，不表示服务器实际运行在开发环境，不要将生产环境切换为 `Development`。

曾出现的错误为 MySQL 自动重试策略与手动事务冲突，代码已移除 `EnableRetryOnFailure`。如果再次发生，检查服务器是否已经部署包含该修复的最新提交。

### 11.6 HTTPS 反复跳转或日志出现 `Unknown proxy`

如果日志出现：

```text
Unknown proxy: 192.168.88.254
```

先向网络管理员确认该地址确实是 HTTPS 网关，再通过 `Set-ToDo-IisEnvironment.ps1` 设置可信代理。不要关闭 HTTPS，也不要信任任意来源地址。

### 11.7 临时开启和关闭 stdout 日志

仅在 Windows 事件日志没有提供真实异常时临时开启。日志可能包含业务数据或异常参数，不得公开发送。

关闭日志：

```powershell
Import-Module WebAdministration

$sitePath = [string](Get-Website -Name "ToDo2").PhysicalPath
$webConfigPath = Join-Path $sitePath "web.config"

[xml]$webConfig = Get-Content $webConfigPath -Raw
$aspNetCore = $webConfig.SelectSingleNode("//aspNetCore")
$aspNetCore.SetAttribute("stdoutLogEnabled", "false")
$webConfig.Save($webConfigPath)
```

确认问题解决后清理过旧日志，但保留最近一次故障日志供复盘。

## 12. 安全和管理规则

1. 不在 Git、聊天记录、部署脚本或文档中填写真实密码和 Key。
2. 不使用 MySQL `root` 作为网站运行账号。
3. 不向公网开放 MySQL 3306。
4. 不把生产服务器切换为 `Development`。
5. 不在 `C:\Deploy\ToDo-source` 直接改业务代码。
6. 不使用 `git reset --hard`、强制推送或手工覆盖生产数据库来处理普通发布问题。
7. 不修改 `test2.icode8.net` 对应的其他网站。
8. 服务器管理员密码曾通过非专用渠道传递，应尽快轮换，并建议建立独立运维账号。
9. 每次重要发布前备份 MySQL、附件和 Data Protection Keys。
10. 至少保留最近 7 天的数据库和附件备份，并定期验证备份可以恢复。
