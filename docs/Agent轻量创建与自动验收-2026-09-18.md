# Agent 轻量创建与自动验收

## 这轮解决什么

按最新确认的原则：人提出目标，普通任务尽量由系统分配、规划、执行和验收；只有明确要求人工、重要变更、证据不足或自动检查无法判断时才交给人。

会议草稿权限、会议原话校验等上一轮发现的问题，本轮按要求不修改。

## 日常使用

1. 在 Agent 管理点“新建 Agent”，只填名称、主要用途、工作要求，点击“创建并启用”。
2. 用途包括进度与风险分析、日报周报整理、会议内容整理、项目资料整理、公开资料调研。
3. Agent Key、能力标签、提示词、基础工具由服务端按用途生成，模型沿用全局默认值。不要求填写 Token、轮数、测试关键词，不需要单独发布。
4. 创建任务并选择“数字员工”，系统按职责和授权匹配。多个合格候选按待处理工作量选择，数量相同按注册顺序选择，不再要求人挑选，也不引入综合评分。
5. 普通任务在后台生成计划后继续执行；无需先点确认计划。只有明确要求先确认计划、或已有人工调整意见的流程才等待确认。
6. 普通分析和报告交付通过检查后，任务变为已完成，进度 100%，交付显示“自动验收通过”，不发送人工验收待办。
7. 未自动通过时保留结果，在“待我处理”和任务详情说明需要人处理的原因；不会因复核服务不可用而把业务执行重跑。

## 技术配置放在哪里

新建页面没有“高级设置”，只有三个业务字段。新建的轻量 Agent 编辑页仍是简单表单，另提供维护人员使用的技术配置链接。

已有自定义 Agent 保持原配置编辑入口，不自动重写历史提示词或扩大权限。轻量编辑保留模型、已有工具授权、资料范围、停用状态与历史版本；改变用途需到技术配置核对权限，避免看似只改一个选项却扩大能力。

资料整理仍需要项目管理员授予资料分类读取权限。公开调研需要现有搜索服务配置；选择用途不会自动购买服务、填写密钥或授权其他项目。

## 自动验收边界

自动验收不是执行 Agent 自己宣布“成功”，由以下两层检查决定：

- 服务端硬检查：明确工作要求、实际资料读取记录、执行未到轮数上限、没有未完成子任务或其他待处理工作、工具无失败/拒绝/未决状态，没有高风险或人工审批操作。要求联网时必须有检索来源；要求保存报告时必须能找到本次执行实际创建的同项目报告。
- 独立无工具复核：对照任务要求、实际资料、工具记录和产物逐项检查。返回结构必须完整，每项依据必须能逐字定位到提供的资料；不采用模型自报分数或置信度。

复核期间再次检查来源、任务和权限变化。要求变化、取消或改派时不把旧结果当作新要求的完成。自动验收有单独状态、策略标识及审计事件，不冒充某个人点击通过，也不混入人工验收通过率。复核模型用量计入对应执行会话。

当前自动验收主要覆盖普通只读分析、资料整理和报告生成，不自动通过重要项目/任务变更、创建任务等尚未纳入产物核验的流程。原有中风险工具 AI 审核、高风险人工审批、幂等、重试、项目权限及资料权限继续有效。

独立模型复核不能保证现实世界事实绝对正确。它仍依赖输入资料完整性和模型能力；自动检查覆盖不了的工作会保留交付、转人工，不伪装成功。

## 兼容与验收

- 没有新增数据库表或列。新增枚举值区分自动验收，不删除已有数据。
- 旧的待确认计划与待验收记录不会批量自动通过；新入队普通任务采用自动流程。
- 明确人工确认的接口和高风险工具审批仍保留。
- 原演示脚本兼容“待人工确认”和“已确认完成”，不再把自动完成的任务误判为等待超时。
- 运行中的版本按对应历史配置验收，不拿新配置里的标准替换旧标准。

建议本地或部署后验收：

1. 新建“进度助手”，只填三个字段，确认立即启用且生成配置历史。
2. 创建只读进度分析任务，描述清楚要列出的成果和依据，观察后台规划、执行与自动完成。
3. 让两个同用途 Agent 接单，验证自动选择且每个任务只有一个执行工作项。
4. 生成并保存一份报告，确认实际报告存在后才可能自动完成。
5. 在任务中写明“人工验收”，确认仍进入人工处理。
6. 使用无来源、失败工具、联网无结果等情况，确认没有假完成。
7. 执行中修改要求或撤销权限，确认旧结果不会被自动验收。
