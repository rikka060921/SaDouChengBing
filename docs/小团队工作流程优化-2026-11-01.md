# 小团队工作流程优化

## 目标与范围

针对三四人团队每天“找到工作 → 读取资料 → 更新进展 → 提交成果 → 验收 → 复用工作记录”的路径，减少页面来回跳转和重复输入。沿用任务、资料、会议、审批与日报现有数据，不新增待办生命周期、组织层级或强制配置向导。

没有重写 Agent 调度、工具审批或自动验收；没有删掉技术人员的高级配置。普通人工任务仍需要现有审核角色验收，不允许负责人自行绕过验收改为 100%。

## 改了什么、为什么

### 入口一致

登录表单保留经过 `IsLocalUrl` 校验的返回地址，成功后使用 `LocalRedirect`。外站和协议相对地址一律回到待我处理；登录失败也保留安全地址。根路径 `/`、`/Index` 不再显示另一套旧项目列表，统一跳转工作台。项目列表功能仍在 `/Projects`。

### 待我处理与日常工作

- 本人工作仅列出有项目权限、本人承担、活跃项目中尚可推进的人工任务，按截止时间（无期限在后）、优先级、ID 排序，最多 6 项，其余跳转既有“我的工作”。
- 直接更新 0—99% 进度和最多 1500 字说明；提交验收必须说明成果和核验方式。复用 `TaskProgressService`，任务、评论、日志和验收提醒一次保存，保留版本冲突校验。
- 正常更新进展不额外发通知；提交验收才提醒有效审核人，不能自行验收。
- 管理人员只看到本人管理的活跃项目概览，系统管理员按原权限范围查看。阻塞指 Agent 失败/暂停或返工至少 2 次；与逾期、待验收可重叠，不是新的统计口径或独立任务。
- 有优先或逾期事项时，日常工作区默认折叠，先露出紧急提醒；提交失败时展开并保留输入。提醒仍沿用原有去重、优先级与分页规则。

### 项目资料网页校订

- 当前版本 `.md`、`.markdown`、`.txt` 出现“编辑正文”。与上传权限一致，当前活跃项目成员可校订文本；无权成员、停用账号、已归档项目不可写。
- 只接受有效 UTF-8 文本（可有 UTF-8 BOM），上限 10 万字符/2 MB。其他编码明确提示转换，不悄悄保存乱码。Office/PDF 原件仍需下载处理，不伪装为在线排版编辑器。
- 保存调用已有版本服务，保留原文件、分类、版本与来源。旧页面不能覆盖已更新的资料；用户输入在业务失败或冲突后保留，并提示复制后刷新对照。
- 项目管理人员可以校订待审核且未过期的 AI 草稿。只修改草稿，不发布正式资料，不替代原有 Agent 写入权限与审核。
- 草稿正文指纹与条件更新防止校订相互覆盖；审批也对比页面指纹和数据库的正文/文件路径，不能用旧草稿内容发布，驳回也不能覆盖已完成审批。旧客户端省略指纹时保留接口兼容，但数据库条件更新保护仍在。
- 正式资料版本仍使用既有历史版本入口。前次草稿文件保留，操作日志记录旧路径与正文校验值；本轮没有新增完整的“草稿版本浏览器”。
- 提交操作带 Razor 防伪标记，编辑页 `private, no-store`。编辑取消或刷新有未保存提示；不会在浏览器本地长期缓存私有正文。

### Agent、会议与报告

Agent 展示说明真实的持久状态：排队、计划、授权审批都不代表已经完成执行。交付和验收继续看现有成果记录；执行时间线默认收起，分配版本等技术信息可展开，高级配置不变。

会议写入前展示待新增/待更新/已写入数量及缺失信息提醒，基于本次加载，改下拉框后以实际表格为准。概览不是审批规则，也不会擅自删掉行动项或改变原话真实性校验。“检查任务落实情况”沿用现有督办逻辑，满足条件时可能通知相关人员，不是重新调用 AI 解析。

任务内私有 AI 建议可“填入进展说明”，明确不自动保存或发布；已有输入需确认替换，超长结果不自动截断。成员核对事实后自行保存。日报生成继续使用原有服务和权限，提示先记录真实进展、核对“本人更新”和“他人更新”的归因；本轮不把同步生成接口冒称后台异步任务。

### 新项目准备

项目管理人员在项目详情看到成员、资料、任务的轻量检查，直接链接既有页面。AI 资料授权可选，不会自动勾选全部分类；基本准备完成后可选项折叠，不强制新成员做技术配置。不增加数据库字段。

## 验证

初始测试项目因 5 个测试桩缺少最新会议解析接口的取消参数而不能编译；仅补齐测试方法签名后基线为 616/616。新增 `TeamWorkflowTests` 32 项，包括跳转安全、个人范围、管理范围、归档限制、提交冲突、正文保留、草稿发布校验、并发审批及已删除/停用账号拦截等。

```powershell
dotnet test .\ToDo.Test\ToDo.Test.csproj -c Release --no-restore --nologo
dotnet build .\ToDo.sln -c Release --no-restore --nologo
dotnet build .\ToDo.sln -c Debug --no-restore --nologo
```

完整回归 648/648。既有会议详情与会议准备中的 8 处可空引用警告不属于本轮引入问题。

本次默认 Debug 输出被用户正在运行的本地 `ToDo.Razor` 实例锁定，直接构建报 MSB3027/MSB3021。没有终止该实例，改为以下隔离输出构建后验证，不把文件锁误报为源代码错误：

```powershell
$debugOutput = Join-Path (Get-Location) 'artifacts\team-workflow-20261101\debug-output\'
dotnet build .\ToDo.sln -c Debug --no-restore --nologo "-p:OutDir=$debugOutput"
```

Release 与隔离 Debug 均编译通过。验证后对同一、未变更的提交使用同步脚本的 `-SkipValidation`，不为重复验证而关闭用户程序。本地需要停止旧实例、重新构建启动，才会运行新代码。

隔离 SQLite + 本地替身服务、回环地址上的 Edge 浏览器验证 16 项，覆盖负责人、开发成员、新人和无权限成员：根入口、工作范围、进展保存、390px 手机无溢出、正文及草稿校订、冲突保留输入、AI 建议填入但不发布、会议概览、Agent 状态、入门提示、报告入口、登录跳转与受测页面无 HTTP 500。AI 结果使用明确标注的本地模拟数据，不能据此声称真实模型效果或线上部署已验收。日志及截图存于本地忽略的 `artifacts/team-workflow-20261101`。

## 手工验收建议

1. 成员打开任务深链接，未登录时登录后仍回到原任务；外部返回地址不能跳转。
2. 在待我处理更新自己任务，普通进展不额外催办；填写成果后提交验收，审核人收到通知。普通成员看不到管理项目汇总。
3. 成员编辑一份 MD，保存后出现新版本，旧版本可读；两页同时编辑，后一页保存应提示冲突并保留输入。
4. 管理人员校订 AI 草稿，确认仍处于待审核；另一人校订后，旧审批页面必须刷新再审核，不能把旧内容写为正式资料。
5. 查看待确认会议，核对新增与变更；点击检查前了解会更新督办状态、可能发送提醒。
6. 新建项目按提示添加成员、资料和首个任务；不配置 AI 也能推进人工工作。

## 交付边界

无数据库迁移，无新增模型 Key 或运行配置，无正式数据变动。本轮只提交并同步两个代码仓库，不部署 IIS；线上需正常部署新版本后才能看到变化。保留已有项目、任务、会议、资料及高级选项。没有用历史 616 项通过代替本次回归。
