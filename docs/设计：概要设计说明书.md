# 设计：ToDo项目管理系统概要设计说明书

## 1. 引言

### 1.1 目的

本文档旨在为基于 CSharp、EF Core 和 ASP.NET Core Razor 技术栈的 ToDo项目管理系统提供概要设计。它将根据《需求分析说明书》和《需求规格说明书》中定义的功能和非功能性需求，描述系统的整体架构、模块划分、主要组件及其相互关系，为后续的详细设计和开发奠定基础。

### 1.2 范围

本概要设计说明书涵盖了项目管理系统的主要模块，包括用户与权限管理、项目管理、任务模块、分组模块、任务与项目变动日志模块、项目会议纪要模块、项目日报（周报/月报）模块以及AI智能助手模块。它将从宏观层面阐述系统的技术选型、架构模式、数据流向和关键设计考虑，但不涉及具体的类设计、方法实现细节或详细的数据库字段定义。

### 1.3 术语与缩略语

- **EF Core**: Entity Framework Core，.NET 平台下的对象关系映射（ORM）框架。
  
- **ASP.NET Core Razor Pages**: ASP.NET Core 中的一种页面驱动的 Web UI 开发模型。
  
- **CRUD**: Create, Read, Update, Delete（增、查、改、删）。
  
- **Identity**: ASP.NET Core 提供的用户认证和授权管理系统。
  
- **ORM**: Object-Relational Mapping，对象关系映射。
  
- **AI**: Artificial Intelligence，人工智能（系统集成的AI大模型服务）。
  

## 2. 系统概述

### 2.1 系统目标

本系统旨在开发一个高效、易用的 ToDo项目管理系统，核心目标包括：

- 提供完善的用户认证、授权和角色管理功能，确保系统数据安全和用户权限分明。
  
- 实现对项目、任务和分组的有效管理和跟踪，提升项目透明度。
  
- 提升团队协作效率，通过清晰的任务分配、实时状态更新和便捷的信息共享。
  
- 记录关键操作日志，便于审计、问题追溯和责任划分。
  
- 提供数据汇总和统计功能，直观展示项目和任务的整体状态和关键指标。
  
- 规范会议纪要和日报管理，提供统一的平台记录和管理项目会议纪要及成员日报。
  
- 集成AI智能助手，提供任务智能拆分、会议纪要处理、日报自动生成等能力，提升工作效率。
  

### 2.2 系统功能概览

系统将提供以下核心功能：

- **用户与权限管理**：用户登录/登出、个人资料管理、用户列表与管理、用户状态管理、角色分配、权限控制、用户回收站（恢复已删除用户）。
  
- **项目管理**：项目创建、项目列表、项目详情、项目编辑、项目归档、项目加密设置、项目成员管理（基于项目角色）、项目统计。
  
- **任务模块**：任务创建（支持AI智能解析）、任务列表、任务详情、任务编辑、任务状态切换、任务认领、任务指派、任务进度跟踪、任务开始时间管理、任务逻辑删除与恢复、任务统计标签。
  
- **分组模块**：分组创建、分组列表、分组编辑/删除、分组逻辑删除、关联冲突处理、分组任务数量统计。
  
- **任务与项目变动日志模块**：自动日志记录、操作人记录、日志展示、日志格式化。
  
- **项目会议纪要模块**：会议纪要的创建、编辑、查看、逻辑删除和附件管理。
  
- **项目日报（周报/月报）模块**：日报的提交、修改、查看、按类型管理、以及附件上传管理。
  
- **AI智能助手模块**：AI任务拆分、AI会议纪要处理、AI日报生成（按项目汇总）、AI智能任务解析。
  
- **数据统计与报表模块**：项目统计图表、个人工作汇总。
  

## 3. 总体架构设计

### 3.1 架构模式

本系统采用**分层架构（Layered Architecture）**，以实现职责分离、高内聚、低耦合的设计目标。各层之间通过明确定义的接口进行通信，确保系统的可维护性、可扩展性和可测试性。

### 3.2 逻辑分层

系统划分为以下主要逻辑层：

- **表现层 (Presentation Layer - ToDo.Razor)**:
  
    - **职责**: 负责用户界面展示、接收用户请求、数据绑定和基本的用户输入验证。它是用户与系统交互的唯一入口。
      
    - **技术**: ASP.NET Core Razor Pages。
    
- **业务逻辑层 (Business Logic Layer - ToDo.Domain)**:
  
    - **职责**: 包含核心业务规则、业务流程和复杂逻辑处理。它协调数据访问层和表现层，执行权限判断、数据校验、事务管理等。
      
    - **技术**: CSharp 类库，包含AI服务接口实现。
    
- **数据访问层 (Data Access Layer - ToDo.Context)**:
  
    - **职责**: 负责与数据库的交互，包括数据的持久化、检索、更新和删除。它封装了数据库操作细节，提供面向业务逻辑层的抽象接口。
      
    - **技术**: Entity Framework Core (Pomelo.EntityFrameworkCore.MySql)。
    
- **实体层 (Entities Layer - ToDo.Entities)**:
  
    - **职责**: 定义系统中的数据实体模型，直接映射到数据库表结构，包含数据的属性和基本关系。
      
    - **技术**: C# 类库。
    
- **数据库层 (Database Layer)**:
  
    - **职责**: 存储所有业务数据，提供数据的持久化存储、高效的查询和数据完整性保障。
      
    - **技术**: MySQL 8 数据库。

## 4. 模块设计

### 4.1 模块划分

根据需求分析，系统划分为以下主要功能模块：

1. **用户与权限模块**
   
2. **项目管理模块**
   
3. **任务模块**
   
4. **分组模块**
   
5. **任务与项目变动日志模块**
   
6. **项目会议纪要模块**
   
7. **项目日报（周报/月报）模块**
   
8. **AI智能助手模块**
   
9. **数据统计与报表模块**
   

### 4.2 各模块职责与主要组件

#### 4.2.1 用户与权限模块

- **职责**: 负责用户身份验证、授权和角色管理，确保系统访问的安全性和合规性。
  
- **主要功能组件**:
  
    - **用户登录/登出**: 基于 ASP.NET Core Identity 实现，提供安全的登录验证和会话管理。
      
    - **用户添加**: 用户无法自行注册，所有新用户均由系统管理员在后台创建和添加，并设置初始用户名和密码，分配系统角色。
      
    - **个人资料管理**: 允许用户查看和更新自己的个人信息，如真实姓名、性别、身份证号、头像等。这些自定义字段集成在 ApplicationUser 实体中（继承 IdentityUser<int>）。
      
    - **用户列表与管理**: 系统管理员可查看所有用户列表，支持按用户状态（如激活/禁用）进行过滤和搜索，并可禁用或激活用户账号，控制用户对系统的访问权限。
      
    - **用户回收站**: 提供已删除用户的恢复功能，支持查看和恢复被逻辑删除的用户。
      
    - **角色分配**: 系统管理员可为现有用户分配或修改其系统角色，仅有两种系统角色：`systemAdmin`（系统管理员）和 `teamMember`（团队成员）。
      
    - **权限控制**: 基于用户的系统角色和其在特定项目中的身份（通过 ProjectRole 枚举区分：Admin=0 项目管理员，Member=1 项目成员），严格限制其对功能和数据的访问。项目管理员仅在其所属项目中拥有管理权限。
    
- **关联实体**: `ApplicationUser` (IdentityUser<int>), `IdentityRole<int>`, `IdentityUserRole<int>`, `ProjectUser`。
  

#### 4.2.2 项目管理模块

- **职责**: 负责项目的创建、管理、归档和成员协作，是项目生命周期的起点。
  
- **主要功能组件**:
  
    - **项目创建**: 系统管理员可以创建新项目，填写项目名称、详细描述、负责人、需求说明等信息。系统自动记录项目创建人和创建时间。
      
    - **项目列表**: 系统展示所有用户有权限访问的项目列表，支持按项目名称、创建人、状态（进行中 Active、已归档 Archived）进行筛选和排序。
      
    - **项目详情**: 展示项目基本信息、关联任务、项目成员、会议纪要和日报等。
      
    - **项目编辑**: 允许项目负责人修改项目信息，系统管理员可修改所有项目信息。
      
    - **项目归档**: 允许项目管理员将已完成或暂停的项目进行归档，归档项目将不再显示在活跃项目列表中，但数据仍可查询。
      
    - **项目加密设置**: 支持项目可见性设置（IsEncrypted字段：0-公开，1-负责人及成员可见，2-仅负责人可见）。
      
    - **项目成员管理**: 允许项目管理员和系统管理员向项目中添加、移除成员，并管理成员在项目中的角色（Admin-项目管理员，Member-普通成员）。
      
    - **项目统计**: 提供项目概览，如任务完成率、成员活跃度等数据汇总。
    
- **关联实体**: `Project`, `ApplicationUser`, `ProjectUser`。
  

#### 4.2.3 任务模块

- **职责**: 负责任务的创建、分配、状态跟踪和进度更新，是项目执行的最小单元。
  
- **主要功能组件**:
  
    - **任务创建**: 用户在所属项目中创建任务，可定义任务标题(Title)、描述、截止日期、开始时间、优先级(High/Medium/Low)、指派人（可选）、关联分组等。支持AI智能解析文本自动拆分任务。
      
    - **任务列表**: 展示当前项目的所有任务，支持按任务状态(NotStarted/InProgress/Completed/Cancelled)、指派人、认领人、优先级、截止日期等进行筛选、排序和搜索。
      
    - **任务详情**: 展示任务的详细信息，包括任务描述、状态、进度(0-100%)、开始时间、指派人、认领人、变动日志等。
      
    - **任务编辑**: 允许任务创建者、指派人、认领人、项目管理员修改任务信息。
      
    - **任务状态切换**: 提供任务状态流转功能（如：未开始 -> 进行中 -> 已完成 / 已取消）。
      
    - **任务进度跟踪**: 支持设置和更新任务完成进度(0-100%)。
      
    - **任务认领**: 允许未指派任务的成员主动认领任务。
      
    - **任务指派**: 允许有权限的用户将任务指派给其他项目成员。
      
    - **任务逻辑删除与恢复**: 允许有权限的用户逻辑删除任务（任务不显示但数据保留），并可恢复。
    
- **关联实体**: `ToDoTask`, `Project`, `ApplicationUser`, `TaskGroup`, `ChangeLog`。
  

#### 4.2.4 分组模块

- **职责**: 用于任务的分类和组织，提高任务的可管理性和查找效率。
  
- **主要功能组件**:
  
    - **分组创建**: 用户可为项目创建任务分组（如"前端开发"、"后端开发"、"测试"）。
      
    - **分组列表**: 展示项目的所有任务分组，及其包含的任务数量统计。
      
    - **分组编辑/删除**: 允许创建者或项目管理员编辑/删除分组名称。
      
    - **分组逻辑删除**: 支持逻辑删除分组，避免数据丢失，并处理其下关联任务的归属。
      
    - **关联冲突处理**: 删除分组时，提供选项处理其下任务的归属（如移至默认分组或不删除任务）。
      
    - **分组任务数量统计**: 在分组列表中显示每个分组下的任务数量，便于用户快速了解各分组的任务负载。
    
- **关联实体**: `TaskGroup`, `Project`, `ToDoTask`。
  

#### 4.2.5 任务与项目变动日志模块

- **职责**: 负责记录系统中的关键操作和数据变更，提供审计追踪和历史回溯能力。
  
- **主要功能组件**:
  
    - **自动日志记录**: 系统自动记录任务和项目的创建、修改、状态变更、成员变动等关键操作。
      
    - **操作人记录**: 每条日志记录操作的用户信息。
      
    - **日志展示**: 提供统一的日志查询界面，支持按项目、任务、操作类型、操作人、时间范围进行筛选和搜索。
      
    - **日志格式化**: 日志内容以清晰可读的格式展示，便于理解具体变更。
    
- **关联实体**: `ChangeLog`, `ToDoTask`, `Project`, `ApplicationUser`。
  

#### 4.2.6 项目会议纪要模块

- **职责**: 用于记录和管理项目会议的详细内容，促进会议信息的有效共享和追溯。
  
- **主要功能组件**:
  
    - **会议纪要创建**: 允许项目成员上传、编辑其所属项目的会议纪要，支持 Markdown 编辑器，包含会议主题、时间、会议内容等。
      
    - **会议纪要编辑**: 允许会议纪要的上传者、项目管理员在发布后的48小时内进行修改。
      
    - **会议纪要查看**: 所有项目成员可查看其所属项目的会议纪要。系统管理员和项目管理员可查看其有权限的所有会议纪要。
      
    - **会议纪要逻辑删除**: 允许会议纪要的上传者、项目管理员在发布后的48小时内进行逻辑删除。系统管理员可逻辑删除任何会议纪要。
      
    - **附件管理**: 支持上传会议相关的附件（如图片、文档等），通过 MeetingAttachment 实体管理。
    
- **关联实体**: `MeetingMinutes`, `Project`, `ApplicationUser`, `MeetingAttachment`。
  

#### 4.2.7 项目日报（周报/月报）模块

- **职责**: 提供日常工作报告的提交、查看和管理功能，方便团队成员进行工作汇报和项目进度跟踪。
  
- **主要功能组件**:
  
    - **日报提交**: 项目成员可提交日报，填写报告标题、内容（支持 Markdown 编辑器）、所属项目、报告类型（日报/周报/月报）等。
      
    - **日报修改**: 提交日报后24小时内可修改自己的日报内容。
      
    - **日报查看**: 项目成员可查看自身的日报。系统管理员和项目管理员可查看所有人的日报。
      
    - **日报列表与筛选**: 提供日报列表，支持按提交人、项目、报告类型、日期范围进行筛选和搜索。
      
    - **附件管理**: 支持上传日报相关的附件，通过 DailyReportAttachment 实体管理。
    
- **关联实体**: `DailyReport`, `Project`, `ApplicationUser`, `DailyReportAttachment`。

#### 4.2.8 AI智能助手模块

- **职责**: 集成AI大模型能力，提供智能化任务处理和工作汇报辅助功能，提升团队工作效率。
  
- **主要功能组件**:
  
    - **AI任务拆分**: 根据任务标题和描述，智能拆分为多个子任务，支持指定期望拆分数量。
      
    - **AI会议纪要处理**: 智能解析会议纪要内容，提取核心要点和待办事项（含责任人、截止时间）。
      
    - **AI日报生成**: 根据用户当日完成任务、未完成任务和问题情况，自动生成结构化日报。
      
    - **AI日报按项目汇总**: 按项目分类汇总当日所有项目的工作情况，生成整体工作汇报，包含新建项目更新、任务进展、会议纪要、项目日报等。
      
    - **AI智能任务解析**: 将自然语言任务描述文本解析为多个结构化子任务，包含任务名称、描述、截止时间、优先级、状态、分组等信息。
    
- **关联实体**: `AIService` (业务服务类), `AITaskSplitResult`, `AIMeetingSummaryResult`, `AIDailyReportResult`, `AITaskParseResult`。
  
- **技术实现**: 通过 HttpClient 调用外部 AI 大模型 API（OpenAI 兼容格式），配置包括 ApiKey、ApiUrl、ModelName。
  

#### 4.2.9 数据统计与报表模块

- **职责**: 提供项目和个人工作的数据统计与可视化展示，帮助管理层了解整体情况。
  
- **主要功能组件**:
  
    - **项目统计图表**: 展示项目的任务完成率、成员活跃度等关键指标。
      
    - **个人工作汇总**: AI生成个人每日工作情况汇总，包括整体工作总结和按项目分类的详细工作记录。
    
- **关联实体**: `DailyWorkSummary`, `DailyProjectSummaryDetail`。
  

## 5. 数据实体设计（概述）

本系统核心数据实体包括：

- **ApplicationUser**: 继承 IdentityUser<int>，扩展用户基本信息，包含 RealName（真实姓名）、Gender（性别）、Role（系统角色 systemAdmin/teamMember）、Status（用户状态）、IdentityNumber（身份证号）、AvatarUrl（头像URL）、CreatedAt、UpdatedAt、IsDeleted、DeletedAt 等字段。
  
- **Project**: 项目信息，包含 Name（项目名称）、Description（描述）、CreatedAt（创建时间）、CreatedByUserId（创建人）、Status（项目状态 Active/Archived）、LeaderUserId（负责人ID）、LeaderUser（负责人导航）、IsEncrypted（可见性设置 0/1/2）、Requirements（需求说明）、UpdatedAt（更新时间）、IsDeleted（逻辑删除） 等字段。
  
- **ToDoTask**: 任务信息，包含 Title（标题）、Description（描述）、AssigneeId（指派人）、ClaimerId（认领人）、CreatorId（创建者）、Status（任务状态）、Progress（进度 0-100）、GroupId（分组ID）、StartTime（开始时间）、EndTime（结束时间）、Priority（优先级 High/Medium/Low）、CreatedAt、UpdatedAt、IsCompleted（完成标识）、IsDeleted（逻辑删除）、ProjectId（所属项目） 等字段。
  
- **TaskGroup**: 任务分组，包含 Name（分组名称）、ProjectId（所属项目）、IsDeleted（逻辑删除） 等字段。
  
- **ChangeLog**: 记录系统操作日志，包含操作时间、操作人、操作类型、关联实体类型、关联实体ID、变更详情等。
  
- **MeetingMinutes**: 会议纪要，包含 MeetingTitle（会议标题）、MeetingContent（会议内容）、MeetingDate（会议日期）、CreatorId（创建人）、ProjectId（所属项目）、CreatedAt、LastModifiedAt、IsDeleted（逻辑删除）、Attachments（附件集合） 等字段。
  
- **DailyReport**: 日报/周报/月报，包含 ReportTitle（报告标题）、ReportContent（报告内容）、ProjectId（所属项目）、ReporterId（上交人）、ReportType（报告类型 1-日报/2-周报/3-月报）、ReportDate（报告日期）、CreatedAt、LastModifiedAt、IsDeleted（逻辑删除）、Attachments（附件集合） 等字段。
  
- **ProjectUser**: 项目成员关联表（多对多中间表），包含 ProjectId、UserId、IsCreator（是否创建者）、IsProjectAdmin（是否项目管理员）、ProjectRole（项目内角色 0-管理员/1-成员） 复合主键。
  
- **DailyWorkSummary**: AI生成的每日工作情况汇总主表，包含 SummaryDate（汇总日期）、Title（标题）、TotalSummary（整体工作总结）、SummaryStatus（汇总状态 0-待生成/1-已生成/2-生成失败）、CreateTime（AI生成时间）、IsDeleted（逻辑删除） 等字段。
  
- **DailyReportAttachment**: 日报附件，包含 DailyReportId、FileName、FilePath、FileSize、UploadTime 等字段。
  
- **MeetingAttachment**: 会议纪要附件，包含 MeetingMinutesId、FileName、FilePath、FileSize、UploadTime 等字段。
  

这些实体之间通过 EF Core 建立明确的关系（一对多、多对多等）。

## 6. 接口设计（概述）

各逻辑层之间通过接口进行通信。业务逻辑层提供对外服务接口，数据访问层提供数据操作接口。

- **用户服务接口**: 提供用户认证、授权、用户管理等 API。
  
- **项目服务接口**: 提供项目创建、查询、更新、成员管理等 API。
  
- **任务服务接口**: 提供任务 CRUD、状态变更、指派/认领、进度更新等 API。
  
- **分组服务接口**: 提供分组 CRUD、任务归属调整等 API。
  
- **日志服务接口**: 提供日志查询、筛选等 API。
  
- **会议纪要服务接口**: 提供会议纪要的创建、查询、更新、删除等 API。
  
- **日报服务接口**: 提供日报的提交、查询、修改等 API。
  
- **AI服务接口 (IAIService)**: 提供 AI 任务拆分(SplitTaskAsync)、会议纪要处理(ProcessMeetingMinutesAsync)、日报生成(GenerateDailyReportAsync/GenerateDailyReportByProjectAsync)、智能任务解析(ParseTaskAsync) 等方法。
  
- **日报汇总服务接口**: 提供每日工作汇总生成(DailySummaryGenerate)、按项目分类的工作汇总等 API。
  

## 7. 非功能性需求设计考虑

### 7.1 性能设计

- **数据访问优化**: 采用 EF Core 的异步操作，合理使用 `Include` 和 `Select` 进行高效查询，避免 N+1 查询问题。
  
- **缓存机制**: 对不经常变动的数据（如用户角色配置）考虑引入内存缓存或分布式缓存。
  
- **分页与懒加载**: 列表页面实现分页加载，避免一次性加载大量数据；在需要时才加载关联数据。
  
- **索引优化**: 数据库层面建立合适的索引，优化常用查询的性能。
  

### 7.2 安全性设计

- **用户认证与授权**: 基于 ASP.NET Core Identity 实现，支持基于角色的访问控制（RBAC）和基于策略的授权。
  
- **数据传输安全**: 强制使用 HTTPS 协议，确保客户端与服务器之间的数据加密传输。
  
- **输入验证与防范**:
  
    - 严格的服务器端输入验证，防止 SQL 注入、XSS、CSRF 等攻击。
      
    - 使用参数化查询（EF Core 默认支持）。
    
- **权限隔离**: 确保不同角色和用户的数据访问权限严格隔离，防止越权操作。
  
- **日志审计**: 详细记录关键操作日志，包括操作人、时间、内容，便于审计和追溯。
  

### 7.3 可用性设计

- **用户界面**: 简洁、直观、一致的设计风格。
  
- **错误处理**: 提供清晰、友好的错误提示信息，指导用户解决问题。
  
- **用户反馈**: 对于耗时操作提供加载指示。
  
- **兼容性**: 专注于桌面浏览器体验。
  

### 7.4 可维护性设计

- **分层架构**: 确保各层职责清晰，降低耦合度。
  
- **代码规范**: 遵循 CSharp 和 .NET Core 编码规范，编写清晰、可读性强的代码。
  
- **单元测试**: 核心业务逻辑编写单元测试，使用 XUnit 和 Moq 等工具。
  
- **依赖注入**: 广泛使用依赖注入，提高模块的独立性和可测试性。
  
- **文档**: 维护需求文档、设计文档和代码注释。
  
- **日志记录**: 使用成熟的日志框架（如 Serilog）进行系统日志记录，便于故障排查。
  

### 7.5 可扩展性设计

- **模块化设计**: 采用清晰的模块划分，便于未来新功能的添加或现有功能的替换。
  
- **接口化编程**: 各层之间通过接口交互，降低具体实现对调用者的依赖。
  
- **配置化**: 将系统中的可变参数（如数据库连接字符串、API 密钥）进行配置化管理。
  
- **松耦合**: 各模块之间保持最小依赖，便于独立开发和部署。
  
- **微服务（可选）**: 随着系统规模的扩大，可考虑将部分高内聚、低耦合的模块拆分为独立的服务。
