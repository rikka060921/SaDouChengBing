# 设计：ToDo项目进度管理系统详细设计说明书

## 1. 引言

### 1.1 目的

本文档旨在为项目管理系统提供详细设计，作为《概要设计说明书》的补充和深化。它将根据概要设计中确定的架构和模块划分，详细阐述各模块内部的类结构、方法定义、数据流转、接口规范以及数据库表的具体字段和关系，为开发人员提供清晰的实现指导，确保系统开发的规范性和一致性。本系统旨在开发一个高效、易用的 ToDo项目管理系统，核心目标包括提供完善的用户认证、授权和角色管理功能、实现对项目、任务和分组的有效管理和跟踪、提升团队协作效率、记录关键操作日志、提供数据汇总和统计功能以及规范会议纪要和日报管理。

### 1.2 范围

本详细设计说明书涵盖了项目管理系统的所有核心模块：用户与权限、项目管理、任务、分组、任务与项目变动日志、项目会议纪要、项目日报（周报/月报）、AI服务以及每日AI汇总模块。它将深入到每个模块的类、方法、接口以及数据库实体属性的具体定义，并对关键的非功能性需求（如安全性、日志）的实现细节进行描述。本文档不包含具体的UI/UX设计稿，但会概述页面逻辑和所需数据。

### 1.3 术语与缩略语

- **EF Core**: Entity Framework Core，.NET 平台下的对象关系映射（ORM）框架，用于简化应用程序与数据库之间的交互。

- **ORM**: Object-Relational Mapping，对象关系映射。
- **DTO**: Data Transfer Object，数据传输对象，用于在不同层之间传递数据。
- **Service**: 服务层，封装业务逻辑，通常由业务逻辑层提供。
- **Repository**: 仓储模式，封装数据访问逻辑，提供领域对象集合的抽象。

## 2. 系统架构回顾

本系统采用**分层架构（Layered Architecture）**，以实现职责分离、高内聚、低耦合的设计目标。各层之间通过明确定义的接口进行通信，确保系统的可维护性、可扩展性和可测试性。

系统划分为以下主要逻辑层：

- **表现层 (Presentation Layer - ToDo.Razor)**:
    - **职责**: 负责用户界面展示、接收用户请求、数据绑定和基本的用户输入验证。它是用户与系统交互的唯一入口。
    - **技术**: ASP.NET Core Razor Pages。
- **业务逻辑层 (Business Logic Layer - ToDo.Domain)**:
    - **职责**: 封装核心业务规则、权限判断、数据校验和事务管理。它处理来自表现层的请求，并协调数据访问层以完成业务操作。
    - **技术**: CSharp 类库。
- **数据访问层 (Data Access Layer - ToDo.Context)**:
    - **职责**: 封装 EF Core 操作，与数据库进行交互，提供数据的持久化、检索、更新和删除功能。
    - **技术**: EF Core。
- **实体层 (Entity Layer - ToDo.Entities)**:
    - **职责**: 定义数据库实体模型，是业务数据在应用程序中的对象表示。
    - **技术**: C# 类库。
- **数据库层 (Database Layer - MySQL 8)**:
    - **职责**: 用于存储所有业务数据，包括用户、项目、任务、分组、日志、会议纪要和日报等。它提供数据的持久化存储、高效的查询和数据完整性保障。
    - **技术**: MySQL 8 数据库。

#### 3.1.3 权限控制策略

- **基于角色的授权**: 使用 `[Authorize(Roles = "systemAdmin")]` 属性修饰 Razor Pages 或 PageModel 方法，限制只有特定角色才能访问。
    - **系统管理员**: 拥有最高权限，负责整个系统的管理和维护。
    - **团队成员**: 参与项目任务执行的基础角色。
- **基于策略的授权**: 对于更复杂的权限，例如"项目管理员只能管理其负责的项目"，定义自定义授权策略。
    - 定义一个 `ProjectAdminRequirement`。
    - 实现 `ProjectAdminRequirementHandler`，判断当前用户是否为请求项目的管理员。
    - 在 `Program.cs` 中配置策略。
    - 在 Razor Pages 中使用：`[Authorize(Policy = "ProjectAdminPolicy")]`。
- **数据过滤**: 在业务逻辑层查询数据时，根据当前登录用户的角色和项目关联关系，动态构建 LINQ 查询，确保用户只能看到其有权限的数据。

### 3.3 任务模块

#### 3.3.1 功能分解

- **任务 CRUD**: 创建、查询列表（含过滤、分页、按分组和项目过滤）、查看详情、编辑、逻辑删除与恢复。
- **任务状态管理**: 切换任务状态（NotStarted, InProgress, Completed, Cancelled）。
- **任务进度管理**: 0-100%进度跟踪。
- **任务分配**: 任务认领（团队成员认领未指派任务）、任务指派（项目管理员指派任务给团队成员）。
- **AI智能拆分**: 输入自然语言描述，AI拆分并批量创建任务。

## 5. 非功能性设计考虑 (完善)

### 5.1 安全性设计

- **用户认证与授权**: 基于 ASP.NET Core Identity 实现，支持基于角色的访问控制（RBAC）和基于策略的授权。系统用户由系统管理员添加，无法自行注册，确保用户身份受控。
- **数据传输安全**: 强制使用 HTTPS 协议，确保客户端与服务器之间的数据加密传输。
- **输入验证与防范**:
    - 严格的服务器端输入验证，防止 SQL 注入、XSS、CSRF 等攻击。
    - 使用参数化查询（EF Core 默认支持）。
- **权限隔离**: 确保不同角色和用户的数据访问权限严格隔离，防止越权操作。特别是项目管理员的权限是项目限定的，而非全局的。
- **日志审计**: 详细记录关键操作日志，包括操作人、时间、内容，便于审计和追溯。
- **AI服务安全**: API密钥配置在appsettings.json，不在前端暴露。

### 5.2 可用性设计

- **用户界面**: 简洁、直观、一致的设计风格。
- **错误处理**: 提供清晰、友好的错误提示信息，指导用户解决问题。
- **用户反馈**: 对于耗时操作提供加载指示。
- **兼容性**: 专注于桌面浏览器体验。

### 5.3 可维护性设计

- **分层架构**: 确保各层职责清晰，降低耦合度。
- **代码规范**: 遵循 CSharp 和 .NET Core 编码规范，编写清晰、可读性强的代码。
- **单元测试**: 核心业务逻辑编写单元测试，使用 XUnit 和 Moq 等工具，实践测试驱动开发（TDD）理念。
- **依赖注入**: 广泛使用依赖注入，提高模块的独立性和可测试性。
- **文档**: 完善的设计文档、API 说明和环境部署指南。

### 5.4 性能设计

- **数据库优化**:
    - 合理设计数据库索引，优化常用查询的性能。
    - 对于大数据量查询，考虑分页加载和延迟加载。
- **代码优化**:
    - 避免 N+1 查询问题，合理使用 EF Core 的 Include 和 Select。
    - 减少不必要的计算和 I/O 操作。
- **AI服务性能**: 设置合理的超时时间（30秒），使用低温度参数（0.3）确保输出稳定。

### 5.5 可扩展性设计

- **模块化**: 各模块独立设计，便于未来新增功能或替换现有模块。
- **接口定义**: 各层之间通过接口进行通信，方便切换具体实现。

## 6. 部署与环境要求 (补充)

- **开发环境**:
    - **IDE**: Visual Studio 2022 或更高版本。
    - **SDK**: .NET 8 SDK。
    - **数据库**: MySQL 8 客户端和服务器。
    - **版本控制**: Git 客户端 (如 TortoiseGit)。
    - **数据库管理工具**: Navicat。
- **测试环境**:
    - **配置**: 模拟生产环境的配置，包括操作系统、.NET Runtime 和 MySQL 数据库。
    - **用途**: 用于集成测试、性能测试和回归测试。
- **生产环境** (IIS 部署，可选项 Docker):
    1. **发布应用程序**: 使用 `dotnet publish` 命令发布 ASP.NET Core 应用，生成可部署文件。
    2. **安装 .NET Core Hosting Bundle**: 在 IIS 服务器上安装对应版本的 .NET Core Hosting Bundle。
    3. **配置 IIS**:
        - 创建新的应用程序池，.NET CLR 版本设为"无托管代码"。
        - 添加新网站，指向发布文件夹的 `wwwroot` 目录。
        - 配置绑定：HTTP 80 或 HTTPS 443。
    4. **配置 `web.config`**: 确保发布文件夹中 `web.config` 文件存在且配置正确。
- **AI服务配置**:
    - 在 `appsettings.json` 中配置 AI 节点：
    ```json
    {
      "AI": {
        "ApiKey": "your-api-key",
        "ApiUrl": "https://api.deepseek.com/chat/completions",
        "ModelName": "deepseek-chat"
      }
    }
    ```
- **数据库部署**: 在生产环境中部署 MySQL 8 数据库。
