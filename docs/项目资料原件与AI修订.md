# 项目资料：原件、AI 正文与修订稿

## 使用边界

- 上传原件按原始字节保存；下载不会转换格式。不要用「AI 正文提取」核对 WPS/Office 的字体、分页、图片或复杂表格。
- PDF、PNG、JPEG、WebP 可通过权限校验后的同站入口预览原件；Word、PPT、Excel 请下载后用 WPS/Office 打开。不把私有资料地址发送给第三方在线预览服务。
- 正文提取用于检索和 AI 上下文。Word 保留段落/表格顺序，PPT 按实际幻灯片顺序提取；不承诺提取与原件排版一致。损坏文件、纯扫描 PDF、超长正文会明确提示，不将错误提示当作正文交给 AI。
- 图片文件可交给明确配置图片能力的模型。当前不自动 OCR 扫描 PDF，也不自动识别 Office/PDF 中的嵌入图片；请将需识别的图片单独上传。文本提取遗漏图片时，不能声称已经理解整份图文文档。

## 修订与权限

- 资料页 AI 修改选择已启用且具有该分类写入授权的 Agent，使用其运行版本的模型、工作要求和调用限制。
- `.md/.markdown/.txt` 修订后创建同名新版本，保留历史。Word/PDF/图片等原件的修订保存为 `原文件名_AI修订.md`，原件继续保留；不是直接编辑 Office 排版，也不会把 Markdown 字节命名为 `.docx`。
- 修订稿说明记录原资料 ID、来源版本、文件名与修改要求。旧版本草稿不会覆盖新版本，回滚后再次修订保持唯一当前版本。
- 草稿由项目负责人、项目管理员或系统管理员审核。正式 Agent 工具沿用原有审批策略，项目归档后不再写入。应用时重新检查来源版本、资料分类和 Agent 写入权限。
- Agent 的 `project.document.write` 可传 `documentId` 修订已有资料；新建文本资料可传 `categoryId` 指定自定义分类。后台使用真实来源分类校验，不信任模型声称的分类。正文读取仍按用户可见项目及 Agent 分类授权过滤。

## 图片模型配置（技术人员）

不根据「千问 / GLM / Kimi / DeepSeek」等厂商名称推断能力。必须配置当前实际 API 支持的精确模型 ID，并确保此模型能通过现有 `AI:ApiUrl` 与密钥调用。

```powershell
# 示例占位符须换为供应商实际支持图片输入的模型 ID；不在 Git 中填写密钥。
$env:AI__VisionModels__0 = 'your-actual-vision-model-id'
```

然后在 Agent 高级设置中将模型名设为相同 ID。若 Agent 模型名留空，则使用 `AI:ModelName`，该默认模型也必须在列表中才会收到图片。列表未配置时所有模型按纯文本处理，不会发送图片。

- 图片请求采用现有聊天接口兼容的 `image_url` 内容分段；不是向供应商开放本地路径或下载链接。
- 单张最多 4 MB，单次最多 3 张；验证扩展名与实际文件头。Agent 自动上下文只读取已授权分类内、最新的有限图片，不含未授权资料；未传入的图片不得声称已识别。
- 模型配置只增加输入能力，不扩大项目可见性、分类授权或写入审批权限。
- 若图片模型来自另一个 API 提供商，本轮不自动切换地址或复用其他供应商密钥；需先配置兼容的模型网关/接口。

## 本轮验收

使用隔离 SQLite、测试文件和模型测试桩验证上传字节、正文提取、实际模型参数、修订/审核/历史、图片权限和请求内容；不连接正式数据库、不调用真实付费模型。真实 WPS 文档外观对比、供应商图片识别效果与服务器部署仍需各自验收，不与本地测试混为一谈。
