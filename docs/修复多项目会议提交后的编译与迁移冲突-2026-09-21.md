# 修复多项目会议提交后的编译与迁移冲突

日期：2026-09-21

## 适用情况

用户确认：只在本地拉取新代码后编译报错，未针对这两次新提交执行数据库迁移。本次修复针对该情况，不连接业务数据库，不部署服务器。

## 为什么会报错

`01123fc`（Git 作者 `zhaokewei`，2026-09-19 20:51，“修改会议纪要可选多个项目”）新增了 `20260919102504_InitDB.cs` 及其 Designer。仓库此前已存在 `20260826081313_InitDB.cs` 及其 Designer。

尽管文件名中的时间戳不同，两套文件都在 `ToDo.Context.Migrations` 命名空间声明 `partial class InitDB`。C# 会把它们视为同一个类，导致：

- `CS0579`：`DbContext`、`Migration` 属性重复。
- `CS0111`：`Up`、`Down`、`BuildTargetModel` 方法重复。

后续的 `a68679c` 添加了“粘贴转写文本”来源，但不是这次重复类定义的来源。Git 拉取本身正常，错误发生在编译收到的代码时。

## 修改了什么，为什么这样改

### 1. 移除误加的全量初始化迁移

删除以下两个新文件：

- `ToDo.Context/Migrations/20260919102504_InitDB.cs`
- `ToDo.Context/Migrations/20260919102504_InitDB.Designer.cs`

原因不只是类名冲突：新的 `Up` 方法还会尝试重新创建已经存在的业务表。只把类名改成另一个名字虽然可能通过编译，但仍会留下已有数据库升级时“表已存在”的风险。

保留原来的 `20260826081313_InitDB` 兼容标记及其历史迁移 ID，不改写历史迁移顺序；保留 `20260919105130_AddMeetingMultiProjectSupport` 增量迁移及其 Designer、当前模型快照。删除的是 Git 管理的源码，可从提交历史恢复，不涉及删除数据库或业务数据。

### 2. 同步五处 AI 接口测试替身

会议解析接口新增了可选参数 `List<string>? projectNames = null`，但以下测试中的实现仍是旧的两个参数：

- `AgentEventAutomationTests.cs`
- `AgentFrameworkCompletionTests.cs`
- `AgentProductLifecycleTests.cs`
- `MeetingTaskSyncServiceTests.cs`
- `TeamReportScopeTests.cs`

给这五处实现补齐第三个参数，保持原有桩返回行为不变。可选参数允许调用者省略实参，但接口实现的签名仍必须一致；不修复这一点，解决迁移冲突后测试项目仍不能编译。

### 3. 增加三项迁移安全回归测试

在 `ToDo.Test/MigrationSafetyTests.cs` 中增加：

1. 迁移清单保留原 `InitDB`，不再包含误加的第二个初始化迁移，多项目增量迁移仍然存在。
2. 从前一版生成 MySQL 升级 SQL：只创建 `MeetingMinutesProjects` 关联表，并修改所需的项目字段；不包含删除表、删除字段、清空表或删除数据的操作。
3. 当前 EF 模型与模型快照一致，移除重复初始化迁移没有留下未记录的模型变更。

测试使用固定 MySQL provider 版本离线生成 SQL、比较模型，不使用 `ServerVersion.AutoDetect`，不连接实际 MySQL。

## 没有修改什么

- 没有回退多项目会议、行动项项目归属或粘贴转写文本功能。
- 没有调整生产业务逻辑、跨项目权限策略或页面布局。
- 没有运行 `database update`、启动会自动迁移的业务应用、删除数据库或手工修改迁移历史表。
- 没有把“编译/自动化测试通过”当成完整多项目权限与真实服务器升级验收。

如果其他环境已经登记了被移除的新迁移 ID，需要先核对该环境的 `__EFMigrationsHistory` 和实际结构，不能直接套用“从未执行迁移”的假设。
