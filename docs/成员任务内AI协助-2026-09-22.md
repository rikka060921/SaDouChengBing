# 成员任务内 AI 协助：本地开发与验收记录

## 本轮要解决什么

AI 的使用入口应在成员正在做的事情旁边。普通成员只想理清任务、查漏或整理进展时，不应该先配置 Agent、选择执行器，或把整项任务改派给数字员工。

本轮保留已有数字员工的自动派单、执行和验收流程，另补一条轻量入口：

**人工任务 → 一键选择帮助 → 后台整理 → 当前任务页面查看自己的建议。**

这是对正式自动执行能力的补充，不是把原来的自动任务改成人工逐步审批。

## 已落地

### 1. 三种不用写提示词的帮助

- 梳理下一步：给出优先做的三件事、应产出的成果及完成判断。
- 检查遗漏与风险：根据已有事实指出依赖、缺失信息和最小处理动作，不凭空制造工作。
- 整理进展：把任务状态、进度和评论整理成草稿；没有证据的完成情况必须标为待补充。

自动携带当前任务、项目背景、子任务和评论等授权上下文。使用已有 `task-risk-review` 注册定义的模型设置，协助会话的职责与上下文范围由服务器固定约束，不依赖该 Agent 原来的风险分析提示词。

无新增配置页面、数据表或数据库迁移。已有 Agent 被管理员停用时，不会私自重新启用。

### 2. 不打断正在进行的工作

- 不改负责人、任务进度、任务状态，不自动发布评论，不生成正式交付凭证。
- 建议仅在应用内向发起者本人展示，其他项目成员及管理员不能通过会话页面查看他人的私有协助。
- 请求后后台运行，可继续填写评论；可见页面每八秒检查一次活动请求，完成后停止轮询，不刷新整页。
- 提交时禁用重复点击，并正确保留所选用途字段、防伪令牌和请求标识。
- 相同请求标识通过数据库事务和既有租约主键防重复入队，提交成功后回放同一个结果。
- 不同请求标识仍被视为新请求；本轮没有实现跨标签页的全局单任务限流、预算上限或语义去重。
- 空回复或只有被拦截的工具请求不算成功，进入现有有限重试，耗尽后明确失败。

### 3. 权限由后端执行，不靠前端隐藏

- 请求者必须是有效账号，并具备当前项目访问权限及任务职责；支持负责人、认领人、创建者、审核人、项目负责人、项目管理员和系统管理员的对应范围。
- 任务/项目删除、成员移出、账号停用后，不再返回私有结果或启动协助。
- 任务完成或取消后，可以查看仍有权访问的本人历史建议，但不能再请求或继续执行。
- 任务跨项目移动后，原协助会话不能重新绑定到新项目；需在新上下文重新请求。
- 执行前、上下文读取时及保存模型回复前复核相关权限边界。
- 原生工具、旧文本工具协议、自动完成评论和联网搜索全部由服务器禁止；继续对话也不能通过指令或 allow 标志升级权限。
- 独立会话标识兜底，元数据损坏不会退回可写模式。
- 任务详情及会话页面禁止缓存。状态刷新收到 401/403/404 或登录重定向时清除页面内私有建议与链接。

“私有”指应用访问控制，不代表数据库加密或对服务器运维人员不可见。生成仍使用系统配置的模型服务；“不进行联网搜索”不是“离线模型”。

### 4. 页面和行动中心细节

- 任务要求先展示，AI 协助紧随其后；成员先看清工作，再决定是否需要帮助。
- 浅色、低干扰的协助面板，手机单列，长建议可折叠，可复制完整纯文本。
- 结果用文本渲染，模型返回 HTML 不会被执行。
- 显示“建议已准备好”，与“任务已完成”区分。
- 任务状态和优先级使用中文，修正黄色徽标的文字对比度和原有字号类名。
- 任务详情只提供当前用户能打开的执行对话链接，不影响审批入口。
- Agent 中心及会话页把已经回复的 WaitingHuman 状态标为“已回复，可继续提问”，不再误导为审批待办。
- 最近会话先做权限筛选，再满足可见条数，避免私有或撤权记录把正常记录挤出列表。
- 修复行动中心真实的“计划待确认”被后续 Pending 工作项遮掉的问题；任务改派、项目变化、删除、无权限等过滤保持。

## 手工体验路径

1. 使用对任务有职责的普通成员登录，打开一项尚未结束的人工任务。
2. 在任务描述后找到 AI 帮助，点击“梳理下一步”，应提示已排队或处理中。
3. 等待时填写评论但不发布，确认建议出现后输入仍保留。
4. 复制建议，确认任务负责人、进度和评论数没有因此变化。
5. 换另一成员或管理员，确认看不到原成员的私有结果；有相应职责的人可以发起自己的请求。
6. 使用“整理进展”检查草稿是否依据真实评论，未完成的事项不能被描述成已完成。
7. 原有数字员工任务仍走正式派单/执行/验收流程，不出现这三个轻量协助按钮。

实际生成要求服务端已有可用模型配置且 `task-risk-review` 定义启用；没有配置或服务异常时应展示真实的排队、重试或失败状态，不伪装成完成。

## 后续衡量方向

优先拿真实团队任务验证“建议是否可以直接用、少填了多少重复信息、是否减少来回追问”。再按证据推进低风险且可追溯的直接执行、个人工作台的阻塞聚合和成本限额。不要以 Agent 数量或配置项数量作为成熟度指标。

本轮未暂存、提交、推送或部署；修改仍在本地工作区，供验收。
