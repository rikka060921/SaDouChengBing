# 日报周报与 AI 文本资料修订验收

## 本轮的使用入口

1. 工作报告 → 我的日报 → 手动填写／补录。选择项目及工作日期，点击“加载日报”，填写或校订后保存。工作日期可以是过去；填写时间始终是真实保存时间。
2. 工作报告 → 项目周报。管理人员选择项目、开始与结束日期（最多7天，不能预写未来），生成后查看正文及来源快照。
3. 项目资料 → Markdown/TXT 的编辑正文。输入修改要求，选择“AI调整并保存新版本”或“只生成预览”。预览显示按行差异；正常保存、版本历史和恢复入口继续可用。

## 日报来源规则

- 人工内容使用独立、追加修订的记录，不覆盖 `DailyWorkSummary` 的系统整理。原版内容、修订编号和实际填写时间保留；过期页面提交会明确拒绝覆盖，并保留输入。
- “手动触发 AI 生成”不等于“人工填写”。原项目报告中的日报继续显示，不需要迁移或重新录入；它仍遵循原项目报告的编辑规则。
- 新的定时生成及 Agent 工具创建报告都记录生成基线。人批准 Agent 保存不等于人撰写正文，仍标记为 AI／系统生成；历史旧报告不凭空回填未知来源。
- 自动个人日报没有工作记录时可以不生成；该日仍可手动填写。查询空白日也能看到历史记录，不再因没有自动摘要而提前结束整个页面加载。
- 新人工日报只能由本人填写。其他普通成员不能通过更改用户编号读取正文。管理汇总使用项目范围内的分项，不拿个人所有项目的总摘要作为输入。
- 普通项目操作日志只记录人工日报的版本变动，不保存私有正文。正文修订历史有独立的用户及项目访问校验。

## 周报规则

- 来源包括当前项目最新的人工日报版本、个人日报的该项目分项、原项目日报以及所选周期内有变化任务的当前快照。不传入其他项目的分项或个人跨项目总摘要。
- 缺少日报不等于没有工作。人工自述不是系统已验证事实；任务当前快照不是历史时点快照。生成提示要求注明来源种类与编号，冲突并列待核实，不重复计算重叠记录的工作量。
- 生成结果保留来源编号、日期、正文快照与 AI 初始正文；后续原日报变化不改变已经生成的来源快照。
- 同周期默认打开已有周报，减少重复模型调用。重新生成需要显式勾选，创建另一份报告，旧报告和人工修改均保留。
- 含成员日报的周报只向原成员汇总权限范围内的管理人员开放。不能通过切换报告类型或日报日期改变其周期或绕开权限。
- Agent 读取最近报告时也应用该权限：普通成员的模型上下文不包含受限成员汇总和含成员日报的周报，管理人员仅在授权项目范围内读取。
- 授权项目管理人员可修订正文，页面标记“AI生成后人工修订”，保留 AI 初始正文和来源快照。旧编辑页面不能覆盖其他人刚保存的版本。
- 超过来源数量或正文预算时明确拒绝，不静默遗漏来源；模型空答复、工具请求、内容过滤或长度截断不能生成成功报告。

## AI 修改资料的边界

- 本轮直接版本化编辑仅针对 Markdown/TXT。Word、PDF、图片仍保留既有原件及内容提取／草稿流程，不把提取文本伪装成原格式文件。
- AI 使用编辑区当前正文，能包含尚未保存的人工修改；只发送当前资料与修改要求，不自动读取其他项目、不联网、不提供业务写入工具。
- 操作者必须能访问并修改当前项目资料，Agent 必须已启用且拥有精确资料分类的读取、写入授权。生成后再次检查权限和源版本，长请求期间的撤权或归档会阻止保存。
- AI结果被截断、为空或包含工具请求时拒绝覆盖。预览仅改变编辑区，不创建正式版本；直接保存则创建新版本并记录 Agent、修改要求与来源。
- 差异使用按行比较；很大变化退化为整个变化区间对比并明确标注。显示最多200行，不代表正文被截断。完整正文仍可在编辑区检查。
- 在版本历史中恢复后，原件与之前的新版本文件均保留；之后继续修改会创建后续版本。

## 本地回归步骤

使用仓库内现有 .NET 开发环境，在源码根目录运行：

```powershell
dotnet test .\ToDo.Test\ToDo.Test.csproj -c Release --no-restore --nologo
dotnet build .\ToDo.sln -c Release --no-restore --nologo
dotnet build .\ToDo.sln -c Debug --no-restore --nologo
```

`WorkReportAutomationTests` 使用 SQLite 内存数据库和模拟 AI，覆盖人工补录、追加修订、版本冲突、他人访问拒绝、归档／停用／未来日期、空白日历史、旧日期查询、周报项目隔离、来源不可变、人工修订、同周期复用、重新生成另存、模型失败／截断／撤权，以及资料授权、版本、预览、保存、恢复和按行差异。

`MigrationSafetyTests` 离线使用固定版本 MySQL provider 比较模型和生成 SQL，不连接数据库，检查新增迁移不删除或改写历史报告。

2026-11-18 本地验证：修改前为664项测试，其中624通过、40失败；修复租约 provider 兼容问题并加入本轮回归后，711项全部通过、0跳过。Release / Debug 解决方案构建均为0错误；全编译仍有原有8处可空警告。验证记录位于本地忽略目录 `artifacts/work-reports-20261118/`，不随公开仓库发布。

自动化回归不能代替浏览器完整验收、真实模型内容质量、实际 MySQL 迁移和 IIS 部署验收。真实模型验收建议使用独立项目和脱敏资料，记录模型名称、请求时间、费用及实际引用准确性。

## 数据库与部署注意事项

- 新迁移为 `20261117203932_AddWorkReportProvenance`，新增 `daily_report_supplements` 表和 `DailyReport` 的生成正文、来源、周期、人工修订标识等字段。
- 本轮没有连接或迁移本地业务数据库，也没有部署服务器。拉取代码不会自动更新正在运行的旧进程；需要正常编译、重新启动或部署新版本。
- 应用正常启动执行现有初始化流程。Debug 和 Release 都检查是否空库：只有空库走基线初始化，已有库执行已提交的增量迁移。部署前应按原有流程备份数据库和运行时文件。
- 如果某个环境此前已被旧 Debug 逻辑错误标记迁移历史，应先核对实际表结构与迁移历史，不能通过清空数据库、删迁移记录或重复初始化来掩盖问题。
- 文本 AI 调整需已有模型配置及 Agent 分类授权。未配置模型不影响手动日报的填写和查看，不要把密钥写进 Git。

## 仍需单独确认的问题

本轮经确认一并修复会议任务分组：允许无分组；明确清空会同时清除已同步正式任务的分组，修改其他字段不会误清分组；非空分组必须属于目标项目且未删除。项目切换导致旧分组失效时改为无分组并提示。`MeetingActionGroupPageTests` 在 SQLite 内存库中直接调用页面处理器，覆盖行内编辑、弹窗、空值模型绑定、已同步任务、项目切换、非法分组和无权限请求；浏览器交互仍需人工验收。

会议多项目确认权限目前仍按“任一关联项目管理员可确认会议”处理，是否改为每个目标项目分别授权需单独确定，本轮不扩大或重构该权限。服务器是否正常仍需实际环境证据。
